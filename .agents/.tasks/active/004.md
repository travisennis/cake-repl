# Add direct tests for renderTool multi-line argument rendering

**Based on audit finding TESTS-03** — audit commit `05f0916`

## Problem

The `renderTool` function in `internal/ui/timeline.go` has a code path for multi-line argument summaries (primarily the `edit` tool with multiple edits) that is tested only incidentally through the integration test `TestTimelineCacheMatchesFullRender` in `model_test.go`. The multi-line split logic (lines 99–102), the `maxEditPreviews` cap rendering, and the indentation of tool output below the header lack dedicated test coverage.

Current code at `internal/ui/timeline.go:95-110`:

```go
func renderTool(th Theme, tool *ToolBlock, width int) string {
    if tool == nil {
        return ""
    }
    summary := SummarizeToolArgs(tool.Name, tool.Arguments)
    header := th.ToolHeader.Render("⚙ "+strings.ToLower(tool.Name)) + " " +
        th.ToolArgs.Render(firstLineOf(summary, width))
    lines := []string{header}
    // Multi-line argument summaries (edit previews) follow the header.
    if rest := strings.SplitN(summary, "\n", 2); len(rest) == 2 {
        lines = append(lines, th.ToolArgs.Width(width).Render(rest[1]))
    }
    switch {
    case !tool.Done:
        lines = append(lines, th.ToolOutput.Render("  … running"))
    case strings.TrimSpace(tool.Output) == "":
        lines = append(lines, th.ToolOutput.Render("  (no output)"))
    default:
        out := TruncateOutput(tool.Output, DefaultOutputLimit)
        lines = append(lines, indent(th.ToolOutput.Width(width-2).Render(out), "  "))
    }
    return strings.Join(lines, "\n")
}
```

## Fix direction

1. Create `internal/ui/timeline_test.go` (or add to it if created by task 003). Add a function `renderTool(th Theme, tool *ToolBlock, width int) string` — since `renderTool` is unexported, test it through `RenderItem` with `KindTool` items.

2. Test cases:

   - **Nil tool** — `RenderItem` with `Kind: KindTool, Tool: nil` should return `""`
   - **Single-line tool summary** — bash tool with one-line summary (no multi-line split)
   - **Multi-line tool summary** — edit tool with 2 edits, verify the multi-line rest is rendered after the header
   - **Edit preview cap** — edit tool with 5 edits (maxEditPreviews=3), verify the "… N more" line appears
   - **Running state** — `Tool.Done == false`, verify "… running" appears
   - **Empty output** — `Tool.Done == true, Output == ""`, verify "(no output)" appears
   - **Output truncation** — `Tool.Done == true, Output` > DefaultOutputLimit, verify truncation marker appears
