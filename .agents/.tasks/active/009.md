# Markdown rendering in assistant messages

**Based on audit direction finding DIR-01** — audit commit `05f0916`

## Problem

Assistant messages (`internal/app/update.go:137`) are rendered as plain text via `ui.KindAssistant`. Model outputs often contain lists, code blocks, headers, and other markdown formatting that is hard to read as raw text. The README lists this as a known limitation.

Current behavior: `m.appendItem(ui.Item{Kind: ui.KindAssistant, Text: e.Content})` — content is stored as raw string and rendered with `wrap(th.Assistant, it.Text)` — a single lipgloss style with no formatting.

## Investigation needed

Before implementing, determine:

1. **Library choice** — `glamour` is the obvious candidate (Bubble Tea ecosystem, lipgloss-compatible styles, terminal-aware rendering). Evaluate binary size impact (glamour adds ~1.5MB), startup latency, and style customization.
2. **Rendering model** — does glamour render to a single string with ANSI escapes, or is it structured? Can we cache parsed markdown vs. re-rendering on every `View()` call?
3. **Width handling** — glamour needs to know the viewport width. The timeline already wraps at `renderedWidth`. Can glamour render at that width, or does it need re-rendering on resize?
4. **Style/theme integration** — can glamour styles map to the existing `ui.Theme` colors? The REPL has `--no-color` which must still work.
5. **Code block overflow** — code blocks wider than the viewport: wrap or horizontal scroll?

## Relevant files
