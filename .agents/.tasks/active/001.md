# Exit session summary

**Requested by:** Trav

## Goal

When exiting cake-repl, print a one- or two-line summary showing the session ID
and the path to the session data directory on disk.

## Investigation

### Current exit flow

1. `/exit` (or `Ctrl+C` when idle) → `tea.Quit` → `p.Run()` returns in `main.go`.
2. `main.go` currently discards the model: `_, err = p.Run()`.
3. Bubble Tea restores the terminal (alt screen off) before `Run` returns.
4. `main.go` then exits via `return err` — nothing is printed after the TUI.

### Data already tracked

The model (`internal/app/model.go`) already holds everything we need in
`m.session` (`sessionState`):

| Field | Where set | Notes |
|---|---|---|
| `SessionID` | `OnTaskStart` / `OnTaskComplete` | UUID from cake |
| `TaskID` | `OnTaskStart` / `OnTaskComplete` | Task UUID |
| `LastComplete` | `OnTaskComplete` | Full `TaskComplete` event |
| `cfg.Cwd` | From `--cwd` (or `os.Getwd`) | Always set |

The `/session` slash command already formats this data via `sessionInfo()` in
`internal/app/update.go` (line 320).

### Session file location

Cake stores session data in `<cwd>/.cake/sessions/<session-id>/`. cake-repl
must **never read** this directory — the system boundary in
[`ARCHITECTURE.md`](../../ARCHITECTURE.md) forbids it — but **constructing the
path for display is fine** (it is a known convention, not an engine import).

The path would be:

```go
filepath.Join(m.cfg.Cwd, ".cake", "sessions", m.session.SessionID)
```

**Open question:** verify this matches cake's actual layout by checking cake's
`SessionDir` / `--session-dir` logic in the cake source.

### What to print on exit

After the TUI ends, print to **stderr** (so stdout stays clean for piping):

```
cake session: <short-id>  data: /path/to/.cake/sessions/<uuid>/
```

Edge cases:

| Scenario | What to show |
|---|---|
| No session ever started | Nothing (or "no session") |
| Session ID known | Short ID + full path |
| Session failed/canceled | Still show the session ID if we have one |
| `--resume` specified but not yet used | Show the resume ID (we may not have a session dir yet) |

### Implementation sketch

Staged approach:

**Stage 1 — plumbing (minimal)**

1. In `main.go`, change `_, err = p.Run()` to capture the model:
   ```go
   model, err := p.Run()
   ```
2. After `p.Run()` returns (and the alt screen is restored), type-assert:
   ```go
   if m, ok := model.(app.Model); ok && m.session.SessionID != "" {
       fmt.Fprintf(os.Stderr, "\ncake session: %s  data: %s\n",
           ui.ShortID(m.session.SessionID),
           filepath.Join(m.cfg.Cwd, ".cake", "sessions", m.session.SessionID))
   }
   ```
3. The `ui` package already exports `ShortID`.

**Stage 2 — UI polish (optional)**

- Style the exit summary with lipgloss (same theme as the TUI).
- Show the `/session`-style multi-line summary instead of a single line.
- Handle `exitAfter` (cancel then exit) the same way.

### Risks and open questions

- **Session dir convention.** Cake's `--session-dir` may be configurable in the
  future, making the hard-coded `.cake/sessions/<id>` path wrong. If cake gains
  a way to query the session file path (e.g. `cake session path <id>`), prefer
  that over the convention.
- **Model type assertion.** `tea.Program.Run()` returns `tea.Model`, so we need
  the concrete `app.Model` type accessible from `main.go` — it already is.
- **No session file yet.** When using `--resume`, the session ID is known from
  the flag, but the `.cake/sessions/` directory may not exist on disk until the
  first cake invocation. That's fine — we're showing the *expected* path.
- **Multiple tasks.** The latest session from the last `TaskStart`/`TaskComplete`
  is what we display. If the user ran tasks in different sessions (via `/new`),
  only the last one is shown. That matches the `/session` command behavior.
