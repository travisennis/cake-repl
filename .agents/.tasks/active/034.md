# Investigate event ordering in session history

## Problem

During interactive use, events in the session history sometimes appear out of order. Specifically, a command execution event (showing the command being run) appears *after* the text response that references it. This suggests the stream-json event processing may not be preserving the server-sent order, or timeline rendering may be inserting events at the wrong position.

## Investigation scope

1. Verify that the stream-json parser (`internal/cake/events.go`) preserves the order of events as received from `cake`.
2. Check that `internal/app/update.go`'s `applyEvent` applies events to the timeline in receive order.
3. Check if any async processing, batching, or reordering occurs in the runner (`internal/cake/runner.go`).
4. Check if timeline rendering (`internal/ui/timeline.go`) reorders items.

## Relevant files

- `internal/cake/events.go` — event types and parsing
- `internal/cake/parser.go` — NDJSON parsing
- `internal/cake/runner.go` — subprocess management
- `internal/app/update.go` — event application
- `internal/ui/timeline.go` — rendering

## Deliverable

A brief writeup of findings (add as a research note or directly in the task), with:
- Whether the ordering is actually wrong or just appears wrong
- Where the ordering issue originates if it exists
- Recommended fix
