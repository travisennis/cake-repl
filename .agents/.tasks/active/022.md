# Check scanner errors in loadHistory

**Based on audit finding CORRECT-02** — audit commit `fe9b393`

## Problem

`internal/app/model.go:80-85` — `loadHistory` uses `bufio.Scanner` but
never checks `sc.Err()` after the scan loop. If the scanner hits an I/O
error or a line too long for `bufio.Scanner`'s default buffer (64KB),
entries are silently truncated with no indication.

Current code:

```go
sc := bufio.NewScanner(f)
for sc.Scan() {
    if line := sc.Text(); line != "" {
        entries = append(entries, line)
    }
}
// no sc.Err() check here
```

## Relevant files

- `internal/app/model.go:74-93` — `loadHistory`
- `internal/app/model.go:1-10` — imports (already imports `bufio`, `os`, `strings`)

Out of scope: switching to `bufio.Reader` (the runner uses `bufio.Reader`
for stdout because tool output lines can be very long, but history files
are user-authored prompts and unlikely to have 64KB+ lines).

## Fix direction

1. Add an `sc.Err()` check after the scan loop. Since `loadHistory` has no
   return value and history is best-effort, the error should be silently
   ignored (or logged to the debug log if one is configured, but
   `loadHistory` runs in `New()` before the model is fully initialized, so
   the debug log may not be available yet).

   Simplest fix — just return early on scanner error to avoid processing
   a potentially truncated entry list:

   ```go
   sc := bufio.NewScanner(f)
   for sc.Scan() {
       if line := sc.Text(); line != "" {
           entries = append(entries, line)
       }
   }
   if err := sc.Err(); err != nil {
       return // best-effort: use whatever entries we got
   }
   ```

   Or, if we want to be more defensive, increase the scanner buffer size to
   handle long lines:

   ```go
   sc := bufio.NewScanner(f)
   sc.Buffer(make([]byte, 64*1024), 1024*1024) // 1MB max line
   ```

   Both fixes are independent — the buffer increase prevents silent
   truncation from long lines, and the error check handles I/O errors.

2. Add a test case for the scanner error path (e.g., a file with a line
   longer than the default buffer, or a file that becomes unreadable).
   This pairs with the `loadHistory` test task.
