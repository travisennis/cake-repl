# Add markdown link checking to CI

**Based on `docs` audit finding** — `freshness_enforcement` scored 2/3 because documentation freshness rests entirely on manual diligence with no mechanical enforcement.

## Problem

All internal markdown links across the doc set (`AGENTS.md`, `ARCHITECTURE.md`, `README.md`, `CONTRIBUTING.md`, `docs/guardrails/`, `docs/adr/`) resolve today, but nothing prevents them from breaking as files are renamed, moved, or deleted. A stale or broken link silently degrades agent and contributor navigation.

There is no CI job that checks:
- Internal markdown link resolution (links to other `.md` files in the repo).
- Anchor/heading link resolution within files.
- Whether files referenced in `ARCHITECTURE.md`'s codemap still exist.

## Relevant Files

### Existing (review before changing)
- `.github/workflows/ci.yml` — the CI workflow that runs `just ci`.
- `justfile` — the command catalog; `just ci` is the full gate.
- `.pre-commit-config.yaml` — local pre-commit hooks (code-only today).

### To create or modify
- `.github/workflows/ci.yml` — add a doc-link-check step to the existing CI job.
- Or `justfile` — optionally add a `just docs-check` recipe for local use.
- `docs/guardrails/documentation.md` — document the check as a required surface.

## Grooming Decision (2026-07-03)

**Chosen tool: `lychee` via `lycheeverse/lychee-action`.**

Rationale:
- Mature, widely used, actively maintained single-binary link checker.
- The `lycheeverse/lychee-action` GitHub Action is a zero-config install — a single step in CI with no Node.js or Go toolchain overhead for this purpose.
- Handles anchor links, internal `.md` links, and code-block detection out of the box.
- Supports `.lychee.toml` config for excluding directories and URL patterns.
- Fallback if action proves problematic: `markdown-link-validator` (Go-native, same toolchain as the project). Not chosen as primary because `lychee` is more battle-tested for link-checking specifically.

## Fix Direction

Add a markdown link checker step to the existing CI workflow using `lychee`. The checker must:

1. Resolve all internal markdown links (e.g., `[text](./relative/path.md)`, `[text](../path.md)`, `[text](path.md#anchor)`).
2. Exit non-zero when any link is broken (not `continue-on-error: true`).
3. Be fast enough to not meaningfully increase CI runtime.

### Implementation

Add a step to `.github/workflows/ci.yml`:

```yaml
- name: Check markdown links
  uses: lycheeverse/lychee-action@v2
  with:
    args: --config .lychee.toml --no-progress -- './**/*.md'
  env:
    GITHUB_TOKEN: ${{ secrets.GITHUB_TOKEN }}
```

Create `.lychee.toml`:
```toml
# Only check internal .md links — external URL checking is out of scope.
# Exclude generated/task directories.
exclude = [
  '^https?://',
  '^\./\.git/',
  '^\./\.agents/',
  '^\./dist/',
]
```

Also add `just docs-check` to `justfile`:
```makefile
docs-check:
    lychee --config .lychee.toml --no-progress './**/*.md'
```

And update `docs/guardrails/documentation.md` to mention the link-check step as a required CI verification surface.

### Acceptance criteria

- [ ] CI job or step checks all `*.md` files (except generated/task files) for broken internal links.
- [ ] A broken internal link in any checked file causes CI to fail.
- [ ] `justfile` gets a `just docs-check` recipe (or similar) so the check is runnable locally.
- [ ] `docs/guardrails/documentation.md` is updated to mention the link-check step as a required verification surface.
- [ ] All existing internal links pass the check before the CI job is enabled.
- [ ] No new runtime dependency is introduced to the project itself (CI-only tool).

## Constraints

- The check must run on every PR and push to master, not on a schedule.
- Must not check external/HTTP URLs (those are out of scope for doc freshness; link rot from external URLs is a separate concern).
- Must not check `./.agents/` or `./dist/` — these are generated or agent working records.
- Must not break on code blocks containing markdown-style links (some tools do this unless configured).
- Prefer a tool that the project already has a runtime for (Go) to minimize CI setup complexity.
