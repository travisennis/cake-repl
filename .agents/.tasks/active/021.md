# Deduplicate writeFakeCake test helper

**Based on audit finding TECH-03** — audit commit `fe9b393`

## Problem

The `writeFakeCake` test helper is duplicated identically in two test files:

- `internal/cake/runner_test.go:12-19`
- `internal/app/update_test.go:22-29`

Both write an executable shell script to a temp dir and return its path.

## Relevant files

- `internal/cake/runner_test.go:12-19` — `writeFakeCake`
- `internal/app/update_test.go:22-29` — `writeFakeCake` (identical copy)
- `internal/app/model_test.go` — uses `newLaidOutModel` (test helper pattern)

Out of scope: any other test refactoring.

## Fix direction

Two options:

**Option A (accept the duplication):** The function is 8 lines, stable, and
lives in separate packages' test files. Go doesn't easily share test
helpers across packages without a separate non-test package. Creating a
shared package for 8 lines is more overhead than it saves. Accept the
duplication and close this task as "not worth doing."

**Option B (extract to internal/testutil):** Create
`internal/testutil/fakecake.go` with an exported `WriteFakeCake(t *testing.T, script string) string`
function. Both test files import it. This adds a package for one function,
which conflicts with the project's "no speculative abstractions" style.

**Recommendation:** Option A. The duplication is small, stable, and
isolated to test files. Extracting it adds a package for 8 lines. Record
this as "considered and rejected" and cancel the task.

## Acceptance notes

- [ ] Decision made: either extract to `internal/testutil` (Option B) or
