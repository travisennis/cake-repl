# Make debug log writer concurrency explicit

## Problem
The debug log can be written from both the cake runner goroutine and the Bubble Tea update goroutine. With the current CLI path this is one `*os.File`, which is safe enough in practice for line-oriented writes, but `app.Config.DebugLog` and `cake.Options.DebugLog` are typed as plain `io.Writer`, so the concurrency assumption is not explicit.

## Evidence
- Runner writes `stdout:` and `exit:` lines in `internal/cake/runner.go`.
- App writes `repl:` lines through `logDebug` in `internal/app/update.go`.
- `cmd/cake-repl/main.go` opens one append-only debug log file and passes it through config.

## Relevant Files
- `cmd/cake-repl/main.go`
- `internal/app/model.go`
- `internal/app/update.go`
- `internal/cake/runner.go`

## Fix Direction
Make the concurrency contract explicit with the smallest useful change: wrap the debug writer in a small synchronized writer at the CLI/config boundary. This keeps callers free to pass a normal `io.Writer`, preserves the existing debug output shape, and avoids relying on the current `*os.File` implementation detail.

## Acceptance Notes
- [ ] Debug logging uses a synchronized writer before it reaches both app and runner code paths.
- [ ] Existing debug log output prefixes and raw stream handling remain unchanged.
- [ ] No raw stream content is written outside `-debug-log`.
- [ ] If code changes, run `go test ./internal/app ./internal/cake ./cmd/cake-repl` or broader verification.
