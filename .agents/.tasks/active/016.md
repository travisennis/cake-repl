# Add tests for handleTabComplete cycling state machine

**Based on audit finding TESTS-02** — audit commit `fe9b393`

## Problem

`internal/app/update.go:73-117` — `handleTabComplete` implements Tab
completion cycling with wrap-around, input-change detection, and a
single-match shortcut. `completion_test.go` tests `completeSlash` (the
matching function) but not the cycling state machine in `handleTabComplete`.

The cycling state (`completionPrefix`, `completionMatches`, `completionIdx`)
on the Model is untested. The wrap-around logic (restore original prefix on
full cycle) and the input-change reset are edge-case-prone.

## Relevant files

- `internal/app/update.go:73-117` — `handleTabComplete`
- `internal/app/completion.go` — `completeSlash` (already tested)
- `internal/app/completion_test.go` — existing tests for `completeSlash`
- `internal/app/model.go:40-44` — completion state fields on Model
- `internal/app/model_test.go` — `newLaidOutModel` helper

Out of scope: testing `completeSlash` itself (already covered in
`completion_test.go`).

## Fix direction

Add tests to `internal/app/completion_test.go` or a new
`internal/app/tabcomplete_test.go`:

1. **Single match completes directly** — input `/h`, Tab → input becomes
   `/help`, no cycle state set.
2. **Multiple matches start cycle** — input `/q`, Tab → input becomes
   `/quit`, `completionPrefix` is `/q`, `completionMatches` is `["/quit", "/q"]`.
3. **Cycle advances** — from the above state, Tab again → input becomes `/q`.
4. **Cycle wraps around** — from the last match, Tab again → input restores
   to original prefix `/q`, cycle state reset.
5. **Input change resets cycle** — start a cycle, then change the input,
   Tab → fresh match cycle starts.
6. **Non-slash input is a no-op** — input `hello`, Tab → no change.

Call `handleTabComplete` directly on a `Model` (via `m.handleTabComplete()`)
and verify `m.input.Value()` and completion state fields after each call.
