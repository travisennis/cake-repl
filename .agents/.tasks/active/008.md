# Config file for REPL defaults

**Based on audit direction finding DIR-03** — audit commit `05f0916`

## Problem

All REPL configuration comes from CLI flags. There is no config file for setting persistent defaults like `--model`, `--profile`, `--output-limit`, `--cake-bin`, or `--max-timeline-items`. Users who always want a specific model or profile must type it every invocation.

The flag set is still small (~9 flags), so a config file may not yet be warranted. The question to resolve in grooming: is the flag count high enough now, or should we wait until there are 10+ options?

## Investigation needed

1. **Format** — TOML (via `github.com/BurntSushi/toml`), JSON, or YAML? TOML is the most human-friendly for CLI tools and has good Go support.
2. **Path convention** — `~/.config/cake-repl/config.toml` (XDG), `~/.cake-repl.toml`, or project-local `.cake-repl.toml`?
3. **Merge order** — defaults (hardcoded) < config file < CLI flags. Each layer overrides the previous.
4. **Flag/config parity** — which flags are worth putting in a config file? Flags like `--cwd` and `--continue` are session-specific and don't belong in a config file. `--model`, `--profile`, `--cake-bin`, `--output-limit` are good candidates.
5. **Dynamic reload** — should `SIGHUP` or a slash command (`/config reload`) reload the config while the REPL is running? (Probably not for v1 — only read at startup.)

## Relevant files

- `cmd/cake-repl/main.go` — flag parsing, Config construction
- `internal/app/model.go` — `Config` struct
- `README.md` — new flag/config section

## Constraints

- Config file is optional — no file = current behavior unchanged.
- CLI flag overrides always win over config file values.
- Must be testable without a real config file on disk (use `--config /dev/null` or equivalent).
