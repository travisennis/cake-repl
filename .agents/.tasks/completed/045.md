# Redesign the status line into scannable state and context

## Summary

Redesign the bottom status line so users can quickly distinguish current state from session/context metadata. Today the status line flattens session, idle/running, next run mode, model, and cwd into one reverse-video string, which is compact but visually noisy. A better design should emphasize the operational state while keeping session/model/cwd available and readable.

Written against commit `a9b0ced`.

Depends on task `042` so status rendering can use shared semantic theme roles.

## Evidence

- `internal/app/view.go:25` — `statusLine()` constructs plain string segments for session, state, next run mode, model, and cwd, then delegates one flat render call.
- `internal/ui/status.go:12` — `StatusLine` joins every non-empty segment with ` │ ` and applies one `StatusBar` style to the whole line.
- `internal/ui/theme.go:43` — `StatusBar` is only reverse video; there are no semantic styles for state, labels, values, separators, muted context, or running emphasis.
- `internal/app/view.go:31` — idle/running state is just another segment, despite being the most time-sensitive status information.

## Fix Direction

Update `internal/ui.StatusLine` or introduce a richer status-rendering helper that accepts structured state/context data rather than treating every segment identically. The design should separate the current operational state (`idle`, spinner + `running`) from context (`session`, `next`, `model`, `cwd`) through ordering, labels, or styling while still producing exactly one line at the terminal width. Keep the status line read-only and rendering-only; do not change session state, run-mode behavior, spinner behavior, or CLI flags. If the redesign needs more data than `app.statusLine()` currently has, add only the narrow fields needed for display.

## Outcome

- Replaced flat string segments with a structured `ui.Status` value and a renderer-owned label hierarchy.
- The state now leads in brackets, context fields are explicitly labeled, and the reverse-video bar was replaced by semantic state/key styling with native terminal foreground for values.
