# Deduplicate plural/pluralize naming

**Based on audit finding TECH-02** — audit commit `fe9b393`

## Problem

Two identical functions with different names exist in separate packages:

- `internal/ui/toolblock.go:128-133` — `func plural(n int) string`
- `internal/app/update.go:293-297` — `func pluralize(n int) string`

Both implement the same logic: return `""` if n == 1, `"s"` otherwise.

## Relevant files

- `internal/ui/toolblock.go:128-133` — `plural` (used by `summarizeEdit`,
  `summarizeWrite`)
- `internal/app/update.go:293-297` — `pluralize` (used by
  `completionSummary`)
- `internal/ui/toolblock_test.go` — tests that exercise `plural` indirectly
- `internal/app/update_test.go` — tests that exercise `pluralize` indirectly

Out of scope: any other refactoring.

## Fix direction

The project style avoids speculative abstractions and keeps things minimal.
Two options:

**Option A (preferred — simplest):** Inline the 5-line function in
`update.go` where it's used (one call site in `completionSummary`), delete
`pluralize`. Keep `plural` in `ui/toolblock.go` where it has two call sites.

**Option B:** Export `plural` from `ui` as `Plural` and use it from `app`.
This crosses the package boundary for a trivial function — not worth it.

Follow Option A:

1. In `internal/app/update.go`, replace the `pluralize(e.TurnCount)` and
   `pluralize(e.ToolCallCount)` calls with inline `plural`-equivalent logic,
   or just use a local helper. Actually, since `completionSummary` calls it
   twice, keeping a local `plural` function in `update.go` is fine — but
   then we still have duplication. The cleanest path: inline the ternary
   expression since it's a one-liner.

   Replace:
   ```go
   e.TurnCount, pluralize(e.TurnCount),
   e.ToolCallCount, pluralize(e.ToolCallCount),
   ```
   with inline conditional or a local lambda. Given Go's verbosity, keeping
   a local unexported helper is fine — but name it the same as the `ui`
   one (`plural`) for consistency. The duplication is between packages,
   which is acceptable in Go for a 5-line function.

   **Simplest action:** rename `pluralize` to `plural` in `update.go` for
   naming consistency. The duplication across packages is acceptable for
   such a trivial function and avoids a cross-package dependency.

2. Run tests to verify no behavior change.
