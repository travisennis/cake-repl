# Add direct unit tests for StatusLine, theme defaults, and RenderItems

**Based on audit finding TESTS-02** — audit commit `05f0916`

## Problem

Three rendering functions in `internal/ui` lack direct unit tests:

1. **`StatusLine`** (`internal/ui/status.go:20`) — renders the status bar with segment joining, padding/truncation. Currently only tested through full Bubble Tea integration tests.

2. **`DefaultTheme`** (`internal/ui/theme.go:29`) — returns a Theme struct with 15 lipgloss styles. Zero direct tests. Easy to accidentally change a color or style attribute without noticing.

3. **`RenderItems` / `RenderItem`** (`internal/ui/timeline.go:47,62`) — the timeline item rendering switch (one function per Kind). Currently tested only through the `assertCacheMatchesFullRender` helper in `model_test.go`. A targeted test is faster to both run and debug.

## Relevant files

- `internal/ui/status.go` — `StatusLine` function
- `internal/ui/status_test.go` — currently tests only `ShortID`; add `StatusLine` tests here
- `internal/ui/theme.go` — `DefaultTheme` function
- `internal/ui/theme_test.go` — does not exist yet; create it
- `internal/ui/timeline.go` — `RenderItems`, `RenderItem`
- `internal/ui/timeline_test.go` — does not exist yet; create it
- `internal/ui/toolblock_test.go` — existing test file, pattern to follow for timeline tests

## Fix direction

### Step 1: `StatusLine`

Add tests to `internal/ui/status_test.go`:

- Empty segments (returns just padding)
- Single segment exactly fitting width
- Multiple segments with padding
- Multiple segments wider than width (truncation behavior — `MaxWidth` truncation by lipgloss)
- One segment empty among non-empty (ensure it's excluded from join)

Pattern — existing `ShortID` test:

```go
func TestShortID(t *testing.T) {
    // ... table-driven test
}
```

### Step 2: `DefaultTheme`

Create `internal/ui/theme_test.go`:

- `TestDefaultThemeNotEmpty` — assert every style in the Theme has at least one attribute set (or that `DefaultTheme()` doesn't panic)
- `TestDefaultThemeAsciiDegradation` — set color profile to Ascii, call `DefaultTheme()`, render a simple styled string, assert it returns plain text without color escapes (tests the lipgloss auto-degradation contract)

### Step 3: `RenderItems`

Create `internal/ui/timeline_test.go`:

- `TestRenderItem_AllKinds` — one test per Kind, verifying each produces expected output. Use table-driven tests.
- `TestRenderItems_JoinsWithDoubleNewline` — verify the joining behavior
- `TestRenderItem_NarrowWidth` — `width < 8` should clamp to 8

Follow the pattern from `toolblock_test.go` (table-driven, assertion-focused).

## Implementation

**StatusLine** — 5 tests added to `internal/ui/status_test.go`:
- `TestStatusLine_EmptySegments` — empty segments produce padded line
- `TestStatusLine_SingleSegment` — one segment with padding
- `TestStatusLine_MultipleSegments` — three segments with padding
- `TestStatusLine_Truncation` — content wider than width, MaxWidth truncation
- `TestStatusLine_ExcludeEmpty` — empty segment omitted from join

**DefaultTheme** — `internal/ui/theme_test.go` created:
- `TestDefaultThemeNotEmpty` — forces TrueColor, asserts all non-Assistant styles produce ANSI output; Assistant is plain
- `TestDefaultThemeAsciiDegradation` — sets Ascii profile, verifies no ANSI escapes

**RenderItems/RenderItem** — 4 tests added to `internal/ui/timeline_test.go`:
- `TestRenderItem_NonToolKinds` — table-driven test of all 9 non-tool Kinds with expected symbol/prefix
- `TestRenderItems_JoinsWithDoubleNewline` — two items joined by `\n\n`
- `TestRenderItem_NarrowWidth` — width < 8 clamped to 8
- `TestRenderItem_DefaultBranch` — unknown Kind hits the default/fallback branch

Verified: `go test ./internal/ui/` (all 29 tests pass), `just test`, `just ci` (fmt, vet, race, lint, vuln, build, goreleaser check — all green).

## Maintenance note

When adding a new Kind to `ui.Kind` or a new style field to `Theme`, add a corresponding test case. The rendering switch in `RenderItem` should be kept exhaustive — a test that enumerates all Kinds will flag new additions that need test coverage.
