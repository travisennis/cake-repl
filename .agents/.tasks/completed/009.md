# Markdown rendering in assistant messages

**Based on audit direction finding DIR-01** — audit commit `05f0916`

## Problem

Assistant messages (`internal/app/update.go:137`) are rendered as plain text via `ui.KindAssistant`. Model outputs often contain lists, code blocks, headers, and other markdown formatting that is hard to read as raw text. The README lists this as a known limitation.

Current behavior: `m.appendItem(ui.Item{Kind: ui.KindAssistant, Text: e.Content})` — content is stored as raw string and rendered with `wrap(th.Assistant, it.Text)` — a single lipgloss style with no formatting.

## Decisions (grooming 2026-06-27)

1. **Library**: Yes, use `glamour` — it's from the Bubble Tea ecosystem.
2. **Width handling**: Re-render on resize.
3. **Code block overflow**: Wrap (not horizontal scroll).
4. **Priority**: This is one of the next things to work on.
5. **`--no-color`**: Must still produce readable plain text.

## Implementation notes

- glamour renders to a single string with ANSI escapes. Consider caching parsed markdown vs. re-rendering on every `View()` call.
- Binary size impact (~1.5MB) accepted.
- Style/theme integration: can glamour styles map to the existing `ui.Theme` colors?

## Implementation

- Added `internal/ui/markdown.go` with `RenderMarkdown(text string, width int) string` using glamour's dark style.
- Modified `internal/ui/timeline.go` `KindAssistant` case to call `RenderMarkdown` instead of plain wrapping.
- Color profile: uses `lipgloss.ColorProfile()` so `--no-color` (Ascii profile) passes through to glamour, which strips color codes.
- Leading/trailing newlines from glamour are trimmed for consistent spacing.
- Glamour fallback: if renderer creation or rendering fails, falls back to plain text wrapped at width.
- Incremental render cache: unchanged; `RenderMarkdown` is called per-item from `RenderItem`, which is called only for changed items.
- Resize: `RenderItem` receives the current width and glamour re-renders at that width.
