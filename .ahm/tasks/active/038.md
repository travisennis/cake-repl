# Deduplicate command docs between README.md and CONTRIBUTING.md

**Based on `docs` audit finding** — `single_source_of_truth` scored 2/3 because README.md and CONTRIBUTING.md both list the same `just` commands (~42 lines of overlap), creating drift risk.

## Problem

`README.md` (user-facing, section "Common commands") and `CONTRIBUTING.md` (contributor-facing, section "Command catalog") both list the same set of `just` targets — `build`, `install`, `test`, `test-race`, `fmt`, `fmt-check`, `tidy-check`, `vet`, `lint`, `vuln`, `release-check`, `ci`, `install-tools`, `release`, `run` — each with identical descriptions.

If a command is added, renamed, or removed from the `justfile`, two files must be updated. This has not drifted yet (the docs are well-maintained), but the structural risk is real: one person editing only README.md leaves CONTRIBUTING.md incorrect, and vice versa.

## Relevant Files

### To modify
- `README.md` — section "Common commands" (~20 lines listing `just` targets).
- `CONTRIBUTING.md` — section "Command catalog" (~30 lines listing `just` targets + raw `go` equivalents).

### Read-only context
- `justfile` — the authoritative command definitions.
- `docs/guardrails/documentation.md` — the impact matrix and single-source-of-truth guidance.

## Grooming Decision (2026-07-03)

**Chosen: Option A — CONTRIBUTING.md is the canonical source for command documentation.**

Rationale:
- AGENTS.md already routes agents to CONTRIBUTING.md for commands — this makes that routing authoritative.
- CONTRIBUTING.md has the most complete catalog (just targets + raw go equivalents).
- README.md users still get basic build/install/test/run one-liners in the sections above "Common commands"; the duplicated just-target table is removed and replaced with a link.
- No need to add self-documentation to the justfile (Option C) — the justfile is already the source of truth for tooling, the docs just need to link to one place.

## Fix Direction

1. Remove "Common commands" section from `README.md` (lines from `## Common commands` through the end of the table).
2. Replace with a short referral paragraph in the "Tests" or "Build" section:

   ```markdown
   For all common development commands (build, test, lint, verify, release), see
   [`CONTRIBUTING.md`](CONTRIBUTING.md#command-catalog).
   ```

3. Verify `README.md` still reads coherently — the build/install/test/run sections above it still give users the basic usage, so removing the command table doesn't leave users stranded.

### Acceptance criteria

- [ ] `README.md` no longer lists `just` targets that duplicate `CONTRIBUTING.md`.
- [ ] `CONTRIBUTING.md` is the single canonical source for command documentation.
- [ ] All internal links resolve (the referral link in README.md is valid).
- [ ] The decision (which doc owns commands) is noted in `docs/guardrails/documentation.md` impact matrix if not already implied.

## Constraints

- Keep the basic build/run/test sections in README.md (`go build ./cmd/cake-repl`, `go test ./...`, etc.) — these are one-liners a user needs without opening another doc. Only the duplicated just-target table should be removed.
- Do not move the raw go commands out of CONTRIBUTING.md — they are valuable for contributors without `just`.
- Add a note to the documentation guardrail so future doc changes respect the ownership decision.
