# Resolve the cake session-file path duplication in main

**Code-review finding (2026-07-28).** Involves a small user-visible decision;
left Open.

## Problem

`cmd/cake-repl/main.go` derives cake's private session-file location solely to print an exit hint. Although the file is never opened, this duplicates cake's data-directory environment variable and filename layout, contradicts the documented engine boundary, and can silently become inaccurate. The supported session identifier and `-resume` command provide the useful recovery information without this coupling.

## Options

1. **Drop the path from the hint.** Print the resume command and the session
   id only. Smallest change, fully restores the boundary, loses a convenience.
2. **Move it into `internal/cake` as a declared part of the contract.** Keep
   the output, but put the assumption where the engine contract lives, name it
   explicitly in the guardrail as a documented dependency on cake's data
   layout, and accept that it must track cake releases.
3. **Ask cake for it.** Only viable if cake exposes the path through its CLI;
   out of scope unless that already exists.

Option 1 is the honest reading of the current architecture docs. Option 2 is
defensible but converts an accidental coupling into a maintained one, which
should be a conscious choice.

## Relevant Files

- `cmd/cake-repl/main.go` — remove `sessionFilePath`, `displayPath`, and the `file:` exit line while retaining the resume hint.
- `cmd/cake-repl/main_test.go` — remove tests that encode cake's private storage layout and the now-unused display helper.
- `ARCHITECTURE.md` and `docs/guardrails/cake-integration-and-stream-json.md` — verification sources for the existing engine-isolation contract; no exception should be added.

## Acceptance criteria

- [ ] After a session, stderr shows the supported `cake-repl -resume <uuid>` command and no inferred session-file path.
- [ ] Production Go code no longer duplicates `CAKE_DATA_DIR`, cake's session directory, or its session filename convention.
- [ ] Obsolete helper tests and unused imports are removed.
- [ ] `ARCHITECTURE.md` and the cake-integration guardrail remain accurate without adding an engine-boundary exception.
- [ ] Documentation impact is recorded; no README change is required if the removed hint remains undocumented.
- [ ] `just ci` passes.

## Fix Direction

Choose option 1. Delete the session-file path and display helpers and print only the session UUID through the existing `cake-repl -resume <uuid>` hint. Remove imports and tests made obsolete by that deletion. Do not move the path logic into `internal/cake` or document a new exception. No ADR is required because this restores conformance with the existing accepted architecture rather than introducing a new contract. The README does not document the file hint, so record that no user-documentation edit is needed unless inspection finds another reference.
