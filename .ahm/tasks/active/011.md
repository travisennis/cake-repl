# Interactive session browser

**Based on audit direction finding DIR-04** — audit commit `05f0916`

## Problem

The README documents "No session browser; `/resume` needs a UUID you already know" as a limitation. After running multiple sessions, there is no way to browse, select, or explore past sessions from within the REPL. Users must either remember UUIDs or browse `.cake/sessions/` manually outside the tool.

The `/session` slash command shows the current session state, but there is no list view of past sessions.

## Current status

Cake now exposes `cake sessions list --json`, returning session id, timestamp,
and first prompt for the current working directory. That is a suitable
machine-readable source, but cake-repl's current compatibility contract allows
only prompt-running `cake --output-format stream-json` invocations. Directly
listing `.cake/sessions/` (the original proposal) is prohibited by engine
isolation.

## Blocker

Awaiting an architecture decision on whether cake-repl may expand its external
contract to invoke `cake sessions list --json` as a read-only introspection
subcommand. If approved, create an ADR for the contract expansion and an
ExecPlan for this L-effort feature, link both here, replace the stale
filesystem-listing direction below, and then accept the task.

## Investigation needed

This is a v2 feature and needs significant design before implementation.

1. **Data source** — use `cake sessions list --json` if the contract expansion
   is approved. Never inspect cake's session directory or files directly.
2. **UI component** — a list overlay (Bubble Tea `list.Model` from Bubbles) with arrow-key navigation. Opens over the timeline on a `/sessions` slash command or key binding.
3. **Session metadata** — what to show per session? UUID (short), date from filesystem timestamp, maybe task count. Cannot read cake's internal session files per the engine isolation contract.
4. **Actions** — select to resume (calls `/resume <uuid>`), delete, show details.
5. **Pagination** — if there are many sessions, the list needs to be scrollable or paginated.
6. **Cross-platform directory listing** — `.cake/sessions/` may not exist on first use; graceful empty state needed.

## Relevant files

- `internal/app/commands.go` — new `/sessions` slash command
- `internal/app/keys.go` — potential key binding
- `internal/app/update.go` — new command handling
- `internal/app/model.go` — new UI state (list overlay vs. replacing timeline)
- `internal/ui/` — new rendering component for the session list
- `go.mod` — may need `bubbles/list` if not already imported

## Constraints

- Engine isolation: do not read or list cake session storage directly.
- The only candidate data source is the supported, machine-readable
  `cake sessions list --json` command, contingent on the ADR decision above.
- Must work with `--no-color`.
- Must handle the case where `.cake/sessions/` doesn't exist.
- Must handle the case where the session directory changed between `/sessions` and selecting one.
