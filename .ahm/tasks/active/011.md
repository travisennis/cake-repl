# Interactive session browser

**Based on audit direction finding DIR-04** — audit commit `05f0916`

## Problem

The README documents "No session browser; `/resume` needs a UUID you already know" as a limitation. After running multiple sessions, there is no way to browse, select, or explore past sessions from within the REPL. Users must either remember UUIDs or browse `.cake/sessions/` manually outside the tool.

The `/session` slash command shows the current session state, but there is no list view of past sessions.

## Current status

Deferred to backlog (grooming 2026-06-27). Needs an ExecPlan (L effort) when picked up.

## Investigation needed

This is a v2 feature and needs significant design before implementation.

1. **Data source** — cake stores sessions in `<cwd>/.cake/sessions/<uuid>/`. The REPL can list the directory (but NOT read session file contents — engine isolation boundary). Is a directory listing sufficient (uuid + filesystem metadata), or do we need more information?
2. **UI component** — a list overlay (Bubble Tea `list.Model` from Bubbles) with arrow-key navigation. Opens over the timeline on a `/sessions` slash command or key binding.
3. **Session metadata** — what to show per session? UUID (short), date from filesystem timestamp, maybe task count. Cannot read cake's internal session files per the engine isolation contract.
4. **Actions** — select to resume (calls `/resume <uuid>`), delete, show details.
5. **Pagination** — if there are many sessions, the list needs to be scrollable or paginated.
6. **Cross-platform directory listing** — `.cake/sessions/` may not exist on first use; graceful empty state needed.

## Constraints

- Engine isolation: must not read session file contents, only list directory names.
- Must work with `--no-color`.
- Must handle the case where `.cake/sessions/` doesn't exist.
- Must handle the case where the session directory changed between `/sessions` and selecting one.
