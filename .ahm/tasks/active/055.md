# Cache the glamour renderer instead of constructing one per markdown render

**Code-review finding (2026-07-19), medium confidence on user-visible impact.**

## Problem

`RenderMarkdown` constructs a fresh `glamour.NewTermRenderer` on every call
(`internal/ui/markdown.go:29-34`). Renderer construction is comparatively
heavy (style config, word-wrap setup, chroma machinery), and it runs:

- once per assistant item on append, and
- for *every* assistant item on every width change — `rebuildTimeline`
  re-renders the full timeline (`internal/app/model.go:288-299`), and a
  terminal drag-resize fires this repeatedly.

A resize of a long session with many assistant messages constructs hundreds of
renderers back-to-back.

## Relevant Files

### To modify
- `internal/ui/markdown.go` — `RenderMarkdown`.

### Tests
- `internal/ui/markdown_test.go` — existing coverage should pass unchanged;
  add a case asserting two sequential renders at different widths both produce
  correct output (cache keyed correctly).
- Optional: a `Benchmark` comparing per-call cost before/after.

## Fix Direction

Cache one renderer per (width, color profile) — in practice a single cached
renderer plus its width/profile key is enough, since rebuilds render many
items at one width:

```go
var (
    mdMu       sync.Mutex
    mdRenderer *glamour.TermRenderer
    mdWidth    int
    mdProfile  termenv.Profile
)
```

Rebuild the renderer only when width or profile changes. Keep the existing
fallback-to-plain-text paths and the Ascii-profile strip behavior intact.
`internal/ui` is documented as side-effect-free ("data in, strings out",
ARCHITECTURE.md:62-64) — a private memoization cache is compatible with that,
but guard it with a mutex since nothing else in the package assumes
single-threaded use.

## Acceptance criteria

- [ ] Rendering N assistant items at one width constructs at most one
      renderer.
- [ ] Width and profile changes still produce correctly wrapped/styled output
      (including `-no-color` / Ascii).
- [ ] `go test ./...` and `just test-race` pass.
