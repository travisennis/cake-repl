# Decide whether -cwd should select the project-local config directory

**Code-review finding (2026-07-28).** Ambiguity in intended behavior; left Open.

## Problem

`-cwd` chooses where cake runs, but project-local config is resolved against
the *process* working directory.

`resolveCwd` produces the directory passed to cake
(`cmd/cake-repl/main.go:81-101`), while `config.DefaultPaths` returns a bare
relative filename (`internal/config/config.go:38`):

```go
localPath = ".cake-repl.toml"
```

which `toml.DecodeFile` then resolves against the process cwd. So:

```
cd ~/scratch && cake-repl -cwd ~/other-project
```

runs cake in `~/other-project` while taking project-local defaults from
`~/scratch`. The `~/other-project/.cake-repl.toml` that a user would expect to
apply is ignored, and a stray config in the directory they happened to be
standing in wins.

This matches the README's literal wording ("`.cake-repl.toml` in the current
directory") and ADR 002's contract ("Load `.cake-repl.toml` from the current
working directory"), so it is arguably as-specified — but the specification
predates thinking about `-cwd`, and the resulting split makes "the project"
mean two different directories in one invocation. It also interacts with the
`cake-bin` trust question: the config that selects the executable comes from a
directory the user may not think of as the project.

## Options

1. **Resolve project-local config against the resolved `-cwd`.** Makes "the
   project" one directory. Changes behavior for anyone using `-cwd` today.
2. **Keep current behavior, document it sharply.** State in the README and ADR
   002 that project-local config follows the shell's directory, not `-cwd`.
3. **Search both, with a defined precedence.** More surface, probably not worth
   it.

Option 1 is the least surprising, and `-cwd` usage is likely rare enough that
the behavior change is cheap — but it is a behavior change to a documented
contract, so it needs the decision recorded.

## Relevant Files

- `internal/config/config.go` — `DefaultPaths`.
- `cmd/cake-repl/main.go` — ordering of `resolveCwd` and config loading; note
  `resolveCwd` already runs first, so the resolved directory is available.
- `internal/config/config_test.go`, `cmd/cake-repl/main_test.go`.
- `README.md`, `docs/adr/002-config-file-for-repl-defaults.md`,
  `docs/guardrails/cli-and-user-output.md`.

## Acceptance criteria

- [ ] The relationship between `-cwd` and project-local config is decided and
      implemented.
- [ ] README and ADR 002 state it explicitly, including the `-cwd` case.
- [ ] Tests cover the `-cwd` + project-local config combination whichever way
      it resolves.
