# Session slash commands issued mid-run are silently clobbered on completion

**Code-review finding (2026-07-19).** Behavior verified by code read; whether
it is intended is a judgment call, but it contradicts the message shown to the
user.

## Problem

`submit` parses slash commands *before* the `m.running` check
(`internal/app/update.go:229-247`), so `/new`, `/continue`, and `/resume`
execute while a task is running and mutate `sessionState` immediately
(`internal/app/update.go:263-273`).

When the running task then completes successfully, `OnTaskComplete` re-pins
`NextMode` to `RunResume <session-id>` (`internal/app/session.go:39-47`),
silently undoing the command. The user saw "next prompt starts a fresh cake
session", but the next prompt resumes the old session — the exact behavior the
message denied.

`Ctrl+N` already solves this race with the `newSessionPending` flag
(`internal/app/update.go:144-156`); the slash commands have no equivalent
guard.

## Relevant Files

### To modify
- `internal/app/update.go` — `execCommand` (`CmdNew`, `CmdContinue`,
  `CmdResume` cases), possibly `finishRun`.
- `internal/app/session.go` — if the fix records a pending override in
  `sessionState`.
- `docs/guardrails/session-and-security.md` — run-mode transitions section, if
  behavior is defined rather than rejected.

### Tests
- `internal/app/update_test.go` — issue each session command mid-run, complete
  the run successfully, assert the commanded mode survives (or the command was
  rejected with a clear message).

## Fix Direction

Two reasonable options; pick one:

1. **Reject while running** — mirror the prompt path: append a warning
   ("finish or cancel the running task first") for session commands when
   `m.running`. Simplest, no new state.
2. **Defer the effect** — record the user's override and apply it after
   `OnTaskComplete`, so the explicit command wins over auto-pinning (matches
   how `Ctrl+N`'s `newSessionPending` suppresses the old run's influence).

Either way, `/session`, `/help`, `/clear`, `/exit` remain usable mid-run.

## Acceptance criteria

- [ ] `/new` issued during a run is not silently reverted when the run

- [ ] Same for `/continue` and `/resume <uuid>`.
- [ ] Failed/canceled runs still do not advance the run mode.
- [ ] Guardrail doc reflects the chosen behavior.
- [ ] `go test ./...` passes.
