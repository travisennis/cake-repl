# Code-review cleanup batch: dead code, doc mismatches, small UX nits

Grab-bag of low-severity items from the 2026-07-19 code review. Each is
trivial on its own; batched to keep the backlog tidy. All are high-confidence
findings.

## Items

1. **Dead render path.** `ui.RenderItems` (`internal/ui/timeline.go:70`) is
   only called from tests — it duplicates the cached per-item render path in
   `internal/app/model.go` and can silently drift from it. Remove it (and
   port its tests to `RenderItem`) or mark it as the reference implementation
   used by tests on purpose.
2. **Unused theme fields.** `Theme.Rule`, `Theme.Chrome`, `Theme.Muted`
   (`internal/ui/theme.go`) are set in `DefaultTheme` but never used in
   production code. Remove or wire up.
3. **`config.Load` doc mismatch.** Comment says "a missing or unreadable file
   returns an empty Config without error" (`internal/config/config.go:42-44`),
   but only `os.IsNotExist` is tolerated — a permission error aborts startup.
   Fix the comment (or the behavior, if silent-skip is preferred).
4. **`-config` silently overrides `-no-config`.** When both flags are passed,
   the switch order in `cmd/cake-repl/main.go:152-171` makes `-config` win
   with no diagnostic. Add a validation error in `validateFlags` (it exists
   for exactly this kind of conflict).
5. **README Go version vs go.mod.** README:21 says "Go 1.26.3 or newer";
   `go.mod` declares `go 1.26`, which accepts 1.26.0. Align them.
6. **Misleading reject message after Ctrl+N.** After Ctrl+N cancels a running
   task, submits during the drain window (up to the 3s `WaitDelay`) are
   rejected with "a task is already running — Ctrl+C cancels it"
   (`internal/app/update.go:242-245`) — right after the UI showed "New
   session", and the task is already being canceled. Show a drain-specific
   message (e.g. "waiting for the canceled task to exit…") when
   `newSessionPending` is set.
