# Make the markdown renderer's concurrency contract match its guarantee

**Code-review finding (2026-07-28).** Minor: correct today, misleading as
written.

## Problem

`internal/ui/markdown.go` guards the cached glamour renderer with a package
mutex, but releases it before rendering:

```go
r := getRenderer(width, profile)   // mdMu held inside, released on return
...
out, err := r.Render(text)          // unsynchronized
```

`getRenderer` (`internal/ui/markdown.go:68-89`) locks `mdMu` only around the
cache check and construction. `glamour.TermRenderer` carries internal buffered
state and is not safe for concurrent use, so two goroutines calling
`RenderMarkdown` would race on the shared cached renderer — the mutex prevents
a race on the *cache pointer*, not on the *renderer*.

Nothing is broken: `RenderMarkdown` is only reached from `ui.RenderItem`, which
is only called from `Model` methods on the Bubble Tea update goroutine, so
rendering is single-threaded. `go test -race ./...` passes.

The problem is that the code implies a guarantee it does not provide. A future
caller — a background pre-render, a parallel width-reflow, a test rendering in
parallel — would look at the mutex, conclude the package is concurrency-safe,
and introduce a subtle data race. `ARCHITECTURE.md` describes `internal/ui` as
"pure rendering ... side-effect-free", which reads as safe to call from
anywhere, and this package-level mutable cache is the one place that is not.

## Relevant Files

- `internal/ui/markdown.go` — `RenderMarkdown`, `getRenderer`, the package vars.
- `ARCHITECTURE.md` — the "Pure rendering" invariant, if the contract is
  documented rather than enforced.

## Fix Direction

Pick one and make it explicit:

1. **Enforce it.** Hold `mdMu` across `r.Render(text)` too. Cost is
   serializing markdown rendering, which is already serial in practice, so the
   real cost is approximately zero. Simplest, and makes the package match what
   it looks like.
2. **Document it.** State on `RenderMarkdown` that `internal/ui` rendering is
   single-goroutine by contract and the mutex only protects lazy construction.
   Cheaper, but leaves the trap for whoever adds concurrency later.

Option 1 is preferred: it costs nothing measurable and removes the trap
outright. If option 2 is chosen instead, say so in `ARCHITECTURE.md` next to
the "pure rendering" invariant, not only in a source comment.

## Acceptance criteria

- [ ] Either `RenderMarkdown` is genuinely safe for concurrent use, or its
      single-goroutine requirement is stated where a caller would look.
- [ ] If serialized, no measurable regression in
      `BenchmarkTimelineRenderItem/text`.
- [ ] `go test -race ./internal/ui` passes, including a test that calls
      `RenderMarkdown` from multiple goroutines if option 1 is chosen.
