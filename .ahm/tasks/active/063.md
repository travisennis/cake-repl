# Decide the trust model for cake-bin in project-local config

**Code-review finding (2026-07-28).** Raises a product decision, not a defect.
Decision made 2026-08-01; see below.

## Problem

`cake-bin` can be set from a project-local `.cake-repl.toml`
(`internal/config/config.go:22,38`), and that value becomes the executable
cake-repl spawns (`internal/cake/runner.go:161`):

```go
cmd := exec.CommandContext(ctx, opts.Bin, opts.Args()...)
```

So cloning an untrusted repository and starting `cake-repl` inside it runs an
executable of that repository's choosing — including a relative path resolved
inside the checkout. No prompt, no allowlist, no indication in the UI that the
binary came from a repo-controlled file.

This is the same class of exposure as `direnv`'s `.envrc` or
`.vscode/settings.json` task definitions, and those tools all gate it behind an
explicit per-directory trust step.

## Why this is a decision, not a bug

ADR 002 chose project-local config deliberately, and names "a local cake binary
path" as a *motivation* for having a project-local layer
(`docs/adr/002-config-file-for-repl-defaults.md`). But its decision drivers and
consequences analyze session hijack only — the risk that config could silently
resume or hijack a conversation. Nothing in the ADR considers that the same
mechanism selects which program executes. The exposure may well be acceptable
for a single-user local tool; it has simply never been stated and weighed.

## Options

1. **Accept and document.** Keep current behavior, record the exposure in ADR
   002's consequences and in the README config section, so users know
   `.cake-repl.toml` is executable-selecting and should be reviewed like any
   other repo-controlled config.
2. **Restrict the layer.** Allow `cake-bin` only from the XDG config and
   `-config`/`-cake-bin`, and ignore it (with a visible warning) in the
   project-local file. Keeps `model`, `profile`, `output-limit`, and
   `max-timeline-items` project-local, which is most of the value.
3. **Constrain the value.** Require an absolute path and refuse anything
   resolving inside the project directory.
4. **Trust prompt.** Record approved project-local config files by path and
   content hash; prompt on first use or on change.

Option 2 is the smallest change that removes the exposure while keeping the
feature's stated motivation mostly intact; option 1 is legitimate if the threat
model is explicitly "the user already trusts repos they open".

## Decision (2026-08-01)

Chosen: **option 2 — restrict the layer**, per
[ADR 006](../../../docs/adr/006-project-local-config-cannot-select-the-cake-executable.md).
`cake-bin` may be set only from the XDG config file, the `-config` file, or the
`-cake-bin` flag. A `cake-bin` key in project-local `.cake-repl.toml` is
ignored with a visible startup warning naming the file and key; all other
project-local keys keep their behavior. Precedence: hardcoded default <
XDG/`-config` file < `-cake-bin` flag.
