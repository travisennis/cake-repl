# Stop copying every unrecognized stream line into an unread field

**Code-review finding (2026-07-28).**

## Problem

`ParseLine` materializes the full text of every unrecognized record
(`internal/cake/parser.go:69-71`):

```go
default:
    return Unknown{Type: env.Type, Raw: string(trimmed)}, nil
```

`string(trimmed)` copies the entire line. Nothing in production reads
`Unknown.Raw` — `grep` finds writes in `internal/cake/` and reads only in
tests; `applyEvent` logs `e.Type` alone
(`internal/app/update.go:426-427`).

Today this is nearly free because cake emits few unknown records. But the field
quietly undercuts the forward-compatibility property it was meant to support:
if a future cake adds a high-volume record type this REPL does not decode, every
one of those lines gets fully copied, pushed through the event channel, and held
until GC — the exact scenario "decode forward-compatibly" is supposed to make
cheap.

## Relevant Files

### To modify
- `internal/cake/events.go` — the `Unknown` struct.
- `internal/cake/parser.go` — the `default` branch.
- `internal/app/update.go` — the `cake.Unknown` case, if the debug line should
  carry more detail.

### Tests / verification
- `internal/cake/parser_test.go` asserts on `Raw`; update accordingly.
- `just test`.

## Fix Direction

Either drop `Raw` entirely, or populate it only when it can actually be
consumed. If the intent was always "keep it for debug display" (as the doc
comment on `Unknown` says), the honest version is to log the raw line from the
runner, which already writes every stdout line to the debug log when configured
(`internal/cake/runner.go:220-222`) — meaning the copy in `Unknown` is
redundant with an existing, better-placed mechanism.

Keep `Type`: it is read, and it is what the timeline path needs.

Whichever way it goes, make the doc comment on `Unknown` match — it currently
promises debug display that does not happen.

## Acceptance criteria

- [ ] Unrecognized lines no longer allocate a retained copy of their full text
      on the default path.
- [ ] Forward-compatible decoding is unchanged: unknown types still decode to
      `Unknown` and the stream keeps flowing.
- [ ] The `Unknown` doc comment describes what the type actually does.
- [ ] Parser tests updated.
