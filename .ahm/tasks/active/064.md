# Fix shadowed err that discards the debug-log close error

**Code-review finding (2026-07-28).** Confirmed with a minimal repro of the
same shape.

## Problem

In `run()` (`cmd/cake-repl/main.go:214-225`), the debug-log block declares a new
`err` with `:=` inside an `if` block, shadowing the function's named return:

```go
func run() (err error) {
    ...
    if *debugLog != "" {
        f, err := os.OpenFile(*debugLog, ...)   // NEW err, shadows the named return
        if err != nil {
            return fmt.Errorf("opening -debug-log: %w", err)
        }
        defer func() {
            if closeErr := f.Close(); err == nil && closeErr != nil {
                err = fmt.Errorf("closing -debug-log: %w", closeErr)   // assigns the shadow
            }
        }()
```

The deferred closure captures the block-scoped `err`, so the whole error-
propagation block is dead code. A failed flush or close on the debug log is
discarded and the binary exits 0. The `err == nil` guard is also meaningless —
the shadowed variable is always nil at that point.

Impact is small (the debug log is opt-in and diagnostic), but the code reads as
if it propagates the error and does not.

## Evidence

A standalone program with the identical scoping returns `<nil>` from `run()`
despite the deferred assignment.

`golangci-lint` does not catch this: `govet`'s `shadow` analyzer is off by
default and is not enabled in `.golangci.yml`.

## Relevant Files

### To modify
- `cmd/cake-repl/main.go` — the `-debug-log` block in `run()`.
- `.golangci.yml` — optionally enable `govet`'s `shadow` check.

### Tests / verification
- `cmd/cake-repl/main_test.go`.
- `just lint`, `just test`; `just ci` before handoff.

## Fix Direction

Declare the file handle separately so the assignment targets the named return:

```go
var f *os.File
f, err = os.OpenFile(*debugLog, ...)
```

Then consider enabling `shadow` under the `govet` settings in `.golangci.yml`
so the class is caught mechanically. Enable it as its own step and fix or
justify whatever else it reports; if the noise is not worth it, say so in the
task rather than leaving the decision implicit.

## Acceptance criteria

- [ ] A close failure on the debug log surfaces as a non-zero exit with a

- [ ] The successful path still returns nil and the file is still closed.
- [ ] If `shadow` is enabled, `just lint` passes with no remaining shadow
      findings; if it is not enabled, the reason is recorded here.
