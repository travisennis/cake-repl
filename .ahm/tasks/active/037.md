# Slim AGENTS.md to ~120 lines with tighter directive density

**Based on `docs` audit finding** — `progressive_disclosure` scored 2/3 because AGENTS.md is 174 raw lines, moderately over the ~150-line routing-layer ideal, and could push more detail into linked docs.

## Problem

AGENTS.md is 174 lines. While high-quality and directive-dense, about 30–40 lines could be trimmed by:

1. Consolidating the "Operating Loop" and "Docs & ADR Gate" sections — they contain overlapping directives about when to update docs and when to check the gate.
2. Moving the full `preflight` question list into `docs/guardrails/documentation.md` (which already owns the Docs & ADR Gate rubric) and linking to it.
3. Tightening the "Managed Work Intake" section by moving per-entry-point detail into the docs it references.

The goal is to keep AGENTS.md as a concise map (~120 lines) that routes to deeper sources of truth, without absorbing detail that belongs in linked docs.

## Relevant Files

### To modify
- `AGENTS.md` — the root agent entry point. Trim the sections listed below.
- `docs/guardrails/documentation.md` — absorb any detail moved out of AGENTS.md.

### Read-only context
- `ARCHITECTURE.md` — for the structure of terse, directive-led docs in this project.
- `CONTRIBUTING.md` — already the canonical command catalog; AGENTS.md correctly routes to it.

## Fix Direction

### 1. Consolidate Operating Loop + Docs & ADR Gate

Currently these are separate sections (~22 lines + ~18 lines = ~40 lines). They both describe the workflow from "agent lands on a task" through "before handoff, check docs." Merge them into a single workflow with numbered steps, keeping only the unique directives and removing overlap. Target: ~25 lines.

Specifically:
- The "Docs And ADR Gate" checklist (13 bullet items) can be summarized as "Run the documentation impact matrix check" with a link.
- The `preflight` question list (5 bullet items for area:config etc.) should move entirely to `docs/guardrails/documentation.md`, which already owns that rubric. Replace with a one-liner: "For area:config tasks, run the preflight skill (see docs/guardrails/documentation.md for requirements)."

### 2. Tighten Managed Work Intake

The "Use these entry points" block (~8 lines of bullet definitions) is a list that `ahm context` already handles. Shorten to 2–3 lines giving the default lookup command (`ahm context task`) and a note that per-tool entry points are in `.ahm/tasks/index.md`.

### 3. Tighten workflow routing

Each route currently has a consult-this line pointing to the relevant guardrail/ARCHITECTURE/CONTRIBUTING. These are good — preserve them. But the opening phase-explanation sentence of each route ("Use for changes to...") can be more terse. Current average is ~3 lines per route; aim for ~2.

### Acceptance criteria

- [ ] AGENTS.md is ~120 lines (from 174) without losing any unique routing or safety directives.
- [ ] All content moved out of AGENTS.md is absorbed by `docs/guardrails/documentation.md` or linked to.
- [ ] All existing internal links still resolve (the moved sections are linked, not orphaned).
- [ ] AGENTS.md still leads with project identity, compatibility surfaces, and safety rules.
- [ ] No changes to the "Repository Rules" or "Handoff" sections (these are already at the right length).

## Constraints

- Do not change the compatibility surfaces listed at the top of AGENTS.md.
- Do not remove or shorten the explicit routing to CONTRIBUTING.md for commands.
- Do not delete directives — move or consolidate them. The agent must still be told about preflight, ADR gate, and task intake.
- Preserve the statement "When this file conflicts with a specialized doc for that workflow, the specialized doc wins."
