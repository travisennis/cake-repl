# Make tool output truncation limit configurable

**Based on audit finding DX-03** — audit commit `05f0916`

## Problem

Tool output truncation is hardcoded at `const DefaultOutputLimit = 2000` (`internal/ui/toolblock.go:17`). Users working with tools that produce verbose output (large file reads, comprehensive bash results) hit truncation with no recourse. The truncation marker correctly reports the original byte count, but the user can't expand in place or increase the limit.

## Relevant files

- `internal/ui/toolblock.go:17` — `DefaultOutputLimit` constant
- `internal/ui/toolblock.go:103` — `TruncateOutput(tool.Output, DefaultOutputLimit)` call in `renderTool`
- `internal/app/update.go:248` — `ui.TruncateOutput(res.Stderr, ui.DefaultOutputLimit)` call in `finishRun`
- `internal/app/model.go` — `Config` struct, `New`, `Model`
- `cmd/cake-repl/main.go` — flag parsing, `Config` construction
- `README.md` — known limitations and flags table to update

Out of scope: per-tool output limits, on-demand expansion (that's a separate feature), or changing the truncation behavior (ellipsis marker, line-boundary preference, etc.).

## Fix direction

### Step 1: Make DefaultOutputLimit a package-level variable

In `internal/ui/toolblock.go`, change:

```go
const DefaultOutputLimit = 2000
```

to:

```go
var DefaultOutputLimit = 2000
```

This is safe — no other code ranges over the value or switches on it; it's only read in `TruncateOutput` call sites.

### Step 2: Add OutputLimit to app.Config

In `internal/app/model.go`, add to `Config`:

```go
type Config struct {
    // ... existing fields
    OutputLimit int // 0 means use ui.DefaultOutputLimit default
}
```

### Step 3: Plumb into model construction

In `internal/app/model.go`, `New(cfg Config)`, if `cfg.OutputLimit > 0`, set `ui.DefaultOutputLimit = cfg.OutputLimit`.

A simple assignment at construction time is fine since the model is created once and `DefaultOutputLimit` is read-only after that during the session.

### Step 4: Add CLI flag

In `cmd/cake-repl/main.go`:

```go
outputLimit := flag.Int("output-limit", 0, "max characters of tool output to show (default 2000)")
```

Then set `cfg.OutputLimit = *outputLimit`.

### Step 5: Update README

- Remove "Tool output is truncated at 2,000 characters with no expansion control yet" from known limitations (or reword to note truncation is configurable but not expandable).
- Add `--output-limit <n>` to the flags table.
