# Session slash commands issued mid-run are silently clobbered on completion

**Code-review finding (2026-07-19).** Behavior verified by code read; whether
it is intended is a judgment call, but it contradicts the message shown to the
user.

## Problem

`submit` parses slash commands *before* the `m.running` check
(`internal/app/update.go:229-247`), so `/new`, `/continue`, and `/resume`
execute while a task is running and mutate `sessionState` immediately
(`internal/app/update.go:263-273`).

When the running task then completes successfully, `OnTaskComplete` re-pins
`NextMode` to `RunResume <session-id>` (`internal/app/session.go:39-47`),
silently undoing the command. The user saw "next prompt starts a fresh cake
session", but the next prompt resumes the old session — the exact behavior the
message denied.

`Ctrl+N` already solves this race with the `newSessionPending` flag
(`internal/app/update.go:144-156`); the slash commands have no equivalent
guard.

## Relevant Files

### To modify
- `internal/app/update.go` — reject `CmdNew`, `CmdContinue`, and `CmdResume`
  from `execCommand` while `m.running`.
- `docs/guardrails/session-and-security.md` — document the active-run
  restriction in the run-mode transitions section.

### Tests
- `internal/app/update_test.go` — issue each session command mid-run, complete
  the run successfully, and assert the command was rejected with a clear
  message and did not alter the eventual session pin.

## Fix Direction (grooming decision 2026-07-21)

Reject `/new`, `/continue`, and `/resume <uuid>` while a run is active with a
clear warning to finish or cancel the task first. Do not add another deferred
session-state mechanism: `Ctrl+N` remains the intentional cancel-and-reset
operation, while the three slash commands only mutate idle-state run options.
`/session`, `/help`, `/clear`, and `/exit` remain available during a run.

## Documentation / ADR Notes

- User docs: document the active-run restriction alongside the session slash
  commands in `README.md`.
- Guardrails: update `docs/guardrails/session-and-security.md` so the run-mode
  transition rules state the restriction.
- ADR: not required because this enforces the existing one-process/run-mode
  design and removes contradictory behavior; it introduces no new session
  state or persistence contract.
