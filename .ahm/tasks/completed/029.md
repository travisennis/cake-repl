# Cancel live cake run when Bubble Tea exits with error

## Problem
If `tea.Program.Run` returns an error while a cake subprocess is live, `cmd/cake-repl/main.go` returns immediately and does not cancel the active `cake.Run`. Normal quit paths cancel running work, but the error path can orphan the child process because its context is never canceled by the app.

## Evidence
- `main.run` calls `p.Run()` and returns on error before inspecting the returned model.
- `app.Model` tracks the active run in its unexported `run *cake.Run` field.
- `cake.Run.Cancel` is the process lifecycle hook that sends SIGTERM and falls back to SIGKILL via `exec.Cmd` cancellation behavior.

## Relevant Files
- `cmd/cake-repl/main.go`
- `internal/app/model.go`
- `internal/app/update.go`
- `internal/cake/runner.go`
- `cmd/cake-repl/main_test.go`
- `internal/cake/runner_test.go`

## Fix Direction
Ensure `main.run` cancels any live cake run before returning from a `p.Run()` error path. Prefer a small exported method on `app.Model` such as `CancelRunning` or `Shutdown` that hides the internal `run` field and is safe to call when nothing is running.

Do not weaken the existing normal cancellation behavior, SIGTERM/SIGKILL fallback, or session pinning rules.

## Acceptance Notes
- [x] If `p.Run()` returns an error with a live run in the returned model, the run is canceled before `main.run` returns.
- [x] Calling the cleanup method when no task is running is a no-op.
- [x] Normal `/exit`, Ctrl+C cancellation, and successful completion behavior remain unchanged.
- [x] Focused tests cover the app cleanup method or the main error path without requiring a real `cake` binary.
- [x] Run `go test ./cmd/cake-repl ./internal/app ./internal/cake` and `go test -race -cover ./internal/cake` if runner behavior changes.
