# Retire the ahm v1 surface from guardrails, skills, and moved directories

## Problem

ahm v2 reduces the tool to a records CLI for tasks (`.ahm/tasks/`) and ADRs
(`docs/adr/`). Task 079 realigned `AGENTS.md` with that surface, but five other
places still describe or invoke v1 behavior. Each was confirmed against the
installed binary during task 079's preflight.

- `docs/guardrails/documentation.md:21-22` — "Task, ExecPlan, ADR, and research
  indexes are generated by `ahm`." False in v2: `ahm index --help` regenerates
  task and ADR indexes only. This line directly contradicts `AGENTS.md`.
- `docs/guardrails/documentation.md:51` — the impact matrix's
  managed-work row cites `ahm context ... output source when available`;
  `ahm context` does not exist.
- `docs/guardrails/documentation.md:61-63` — "Managed skill files under
  `.agents/skills/` are owned by `ahm`." In v2 `ahm init` touches only
  `.ahm/` state and generated indexes, and never creates, replaces, or removes
  project files. The three skills are git-tracked project prose, and this line
  currently discourages the very edits they need.
- `docs/exec-plans/active/index.md` and `docs/exec-plans/completed/index.md` —
  untracked files carrying a false banner: "This file is generated by
  `ahm index`. Do not edit it by hand." v2 does not index design plans;
  `docs/workflow/exec-plans.md` calls them ordinary project files.
- `.agents/skills/preflight/SKILL.md:41-56` — the required-context list routes
  through `ahm context task`, `ahm context plan`, `.ahm/exec-plans/active/`,
  and `docs/design-docs/index.md`. `.agents/skills/grooming-backlog/SKILL.md`
  still lists the retired `exec_plan` front-matter field.

Related repository state, not yet reconciled with v2:

- `.ahm/config.json` still reports `version: 0.6.3`; `ahm --dry-run init`
  reports it would rewrite only `.ahm/.gitignore`.
- `.ahm/research/` is a retired family with only an empty scaffold and a stale
  generated index (currently ignored by the managed `.ahm/.gitignore`).

## Decisions

- `.agents/skills/*` are project-owned prose. `ahm` neither creates nor
  overwrites them, so the v1 surface is fixed here rather than upstream.
- Delete `.ahm/research/` (retired family, no content) and the stale
  `docs/exec-plans/*/index.md` files (they claim `ahm` generates them). Keep
  both plan buckets present with `.gitkeep`, because the ExecPlan workflow
  names `docs/exec-plans/active/` as the place to write a plan.
- No `README.md` inside `docs/exec-plans/`: the bucket semantics and the
  ownership boundary are already owned by `docs/workflow/exec-plans.md`, and
  restating them would be a third copy.
- `.ahm/config.json`'s `version` field is not drift; `ahm --dry-run init` is
  silent and `ahm status` validates. Leave it alone.

## Expected Observable Behavior

An agent working in this repository never invokes or is routed to a command
or path the installed `ahm` does not have, and the review skills it depends on
point at `docs/exec-plans/active/` and the project-owned procedure docs.

## Acceptance Criteria

- No document under `docs/`, `AGENTS.md`, or `.agents/` instructs an agent to
  run a command the installed `ahm` does not have.
- Skill context lists point at `docs/exec-plans/active/` and the project-owned
  procedure docs rather than `.ahm/exec-plans/` or `ahm context`.
- No file carries a claim that `ahm` generates or owns it when v2 does not.
- The `.ahm/` state is reconciled with the installed v2 binary.

## Verification

- `rg -n --hidden "ahm (intake|context|audit|onboard|upgrade)|ahm task (groom|work)|\.ahm/exec-plans|docs/design-docs|exec_plan:"`
  returns only historical task records. Hidden paths must be included:
  default `rg` skips `.agents/`.
- `ahm --dry-run init` reports no remaining drift.
- Every relative Markdown link in the edited files resolves.
- Behavior probe deferred: the probe that would establish it is a fresh
  session asked to change review rules, checking that it loads
  `docs/workflow/exec-plans.md` and `docs/exec-plans/` rather than the
  removed `.ahm/exec-plans/` or `ahm context`.

## Acceptance Notes

- `docs/guardrails/documentation.md`: the managed-work bullet now names task and
  ADR records and their generated indexes and calls a design plan an ordinary
  project file; the impact-matrix managed-work row names the task, ADR, and
  ExecPlan workflows; the skill-ownership paragraph now records that
  `.agents/skills/` is project-owned prose that `ahm` neither creates nor
  overwrites.
- `.agents/skills/preflight/SKILL.md`: the required-context list drops
  `ahm context task`, `ahm context plan`, `.ahm/exec-plans/active/`, and
  `docs/design-docs/index.md`, and points at `docs/exec-plans/active/`; the
  discovery example and the M row use the same vocabulary; the "design docs"
  term that only `docs/design-docs/` defined is replaced with this repository's
  surfaces (guardrails, design plans, ADRs) at all six sites.
- `.agents/skills/grooming-backlog/SKILL.md`: the retired `exec_plan`
  front-matter field is replaced by a check that an `L` or `XL` task links a
  design plan under `docs/exec-plans/`.
- Deleted `.ahm/research/` (empty retired scaffold plus a stale generated
  index) and `docs/exec-plans/{active,completed}/index.md` (files claiming
  `ahm` generates them). Both plan buckets are kept in git with `.gitkeep`.
- `ahm init` narrowed the managed `.ahm/.gitignore` from `index.md` to
  `tasks/index.md` and `tasks/*/index.md`, which still covers every index the
  installed binary writes under `.ahm/`; the committed `docs/adr/index.md`
  stays tracked, as `docs/workflow/adrs.md` intends.
- **Preflight** (subagent, M scale, Pass 1 + Pass 2, probes against the
  installed binary in throwaway `/tmp` copies). Two findings applied: the
  impact-matrix row now names the ExecPlan workflow, and the "design docs"
  vocabulary was fixed across the skill rather than in the table cell alone.
  Findings deliberately not applied: the `.ahm/.gitignore` header wording is in
  an `ahm`-owned file; `docs/workflow/exec-plans.md` is a verbatim copy of the
  upstream template, so reflowing its long lines would break the diff against
  upstream for no gain; and the 78 historical records carrying `exec_plan: -`
  are history, which v2 tolerates (`ahm status` reports no errors).
- Docs-only change: `just ci` skipped, because every `ci` target is Go-side.
- Probe still deferred, as recorded under Verification.
