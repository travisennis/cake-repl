# Show working state in the terminal title

## Problem

The terminal title was set once at startup and never changed:
`cake-repl: <absolute working directory>`. The status line and composer both
report running state, but neither is visible when the terminal window is
unfocused, minimized, or reduced to a tab, so there was no way to tell from
outside the window whether cake-repl was waiting for input or mid-task.

Requested by Trav (2026-09-22) alongside a context-window indicator, which is
tracked separately as task 083 and blocked on cake.

## What shipped

- A `[working]` prefix marks a run in flight: `[working] cake-repl: <cwd>`. The
  idle form is unchanged, so the documented title still holds whenever no task
  is running.
- `windowTitle(cwd, running)` in `internal/app/model.go` owns the format, with
  the directory sanitized through `ui.Sanitize` (ADR 005); `Model.titleCmd()`
  wraps it in `tea.SetWindowTitle`. `startRun` and `finishRun` emit it on the
  two transitions of the run state, which are the only writers of `m.running`.
- `main` writes `app.IdleTitleSequence(cwd)` after `Program.Run` returns,
  guarded by an `os.ModeCharDevice` check on stdout. Bubble Tea returns on
  SIGINT and SIGTERM — and, after a recovered panic, with a nil model — without
  ever running `Update`, so those exits never reach the model's own reset; a
  pty probe confirmed both leaks before this was added.

## Acceptance criteria

- The title shows `[working] cake-repl: <cwd>` while a task runs and
  `cake-repl: <cwd>` when the REPL is idle, for every exit path the process can
  take, including an interrupt or signal mid-task.
- The working directory keeps the sanitization the old title applied.
- Red herrings to guard against: interrupting the REPL must not leave a working
  marker in a still-open window, and a redirected stdout must not collect a
  title escape.

## Verification

- `just ci` green on the final tree (`gofmt -l .` clean).
- Unit tests: `TestTitleCmdTracksWorkingState`,
  `TestIdleTitleSequenceRestoresIdleTitle`, `TestFinishRunResetsTitleToIdle`,
  and the updated `Init` title assertions in `internal/app/model_test.go`;
  `finishRun` assertions in `internal/app/update_test.go` now check the
  returned title via the `titleSetBy`/`requireTitle`/`requireBatchTitle`
  helpers.
- End to end: the built binary was driven in a pty against a fake cake
  (`-cake-bin`), capturing the OSC 2 writes. Four scenarios — a normal run,
  `/exit` while running, SIGINT mid-task, SIGTERM mid-task — each end at the
  idle title, and a run with stdout redirected to a file receives no escape
  from `main`.

## Acceptance Notes (2026-09-22)

Implemented and verified as described.

- Title transitions captured in a pty with a fake cake binary:
  `cake-repl: /tmp/titlecheck/cwd` → `[working] cake-repl: /tmp/titlecheck/cwd`
  → `cake-repl: /tmp/titlecheck/cwd`. The pty harness answers Bubble Tea's
  terminal queries (`OSC 11`, `CSI 6n`), which the first attempt did not and
  which made the TUI look inert.
- The interrupt paths were the reason for the design: an earlier revision
  cleared the marker with `tea.Sequence(titleCmd, tea.Quit)` on the quitting
  paths, and the pty capture showed SIGINT and SIGTERM still leaving
  `[working]` behind, because Bubble Tea handles both by returning from `Run`
  without calling `Update`. The final design resets from `main` instead, and
  both scenarios now end idle (verified after the change).
- The panic exit is covered by construction, not by a capture: a recovered
  panic returns a nil model, so the reset cannot depend on the model. Its
  residue (`CancelRunning` needs a model handle and is therefore skipped on that
  path) is pre-existing and left alone.
- `just ci` green: fmt-check, tidy-check, vet, test-race, lint (0 issues),
  deadcode, vuln, build, release-check. `gofmt -l .` clean.
- Two preflight passes (M scale, both via subagent). The second pass found that
  the panic exit was documented but not actually covered by the `ok` assertion,
  and that `IdleTitleSequence` hand-wrote the OSC 2 bytes and justified it with
  a false claim about `x/ansi` being unavailable; both were fixed
  (`IdleTitleSequence(cwd)` is now a package function built on
  `ansi.SetWindowTitle`, so `main` cannot skip the reset by losing the model).
- Not done, deliberately: no `-no-title` style flag (the title is already set
  unconditionally, and a flag would need CLI, README, and guardrail surface for
  an unrequested escape hatch), and no elapsed-time or spinner in the title
  (Trav asked for working versus idle).

## Documentation / ADR Notes

- User docs: `README.md` (Run section) documents the `[working]` prefix and
  when it is removed.
- Guardrails: `docs/guardrails/cli-and-user-output.md` (title paragraph) records
  the prefix, the exit rule (model transitions plus `main` after
  `Program.Run`), and the redirected-stdout caveat.
- ADR: not required. No flag, config shape, persisted state, security boundary,
  or cake invocation contract changed; the title was already a documented
  output string extended in place, and the exit-reset mechanism is local to
  `main`. ADR 005 was consulted because the title carries the working
  directory.
