# Strip terminal control sequences from untrusted stream content

**Code-review finding (2026-07-28).** Confirmed by executing the render path;
see Evidence.

## Problem

Nothing sanitizes ANSI/C0 control sequences out of cake stream content before
it is written to the terminal. `ui.RenderItem` (`internal/ui/timeline.go:71-107`)
passes item text through `lipgloss` styling, which wraps and pads but preserves
every escape byte in the payload.

The content on that path is attacker-influenceable in the normal case: tool
output is the stdout of arbitrary commands and the contents of arbitrary files
in whatever repository cake is working in.

Consequences run from cosmetic to real:

- `lipgloss.Width` does not count C0 bytes, so `\r`, backspace, and cursor-move
  sequences silently corrupt the padding math in `renderTool`
  (`internal/ui/timeline.go:125-156`) and `StatusLine`
  (`internal/ui/status.go:53-56`), breaking frame alignment.
- `CSI 2J` and similar clear or scroll the screen out from under Bubble Tea.
- `OSC 52` writes the user's system clipboard.
- `OSC 8` forges hyperlinks over attacker-chosen text.

This also sits against the guardrail that raw stream content goes only to the
debug log (`docs/guardrails/session-and-security.md`).

## Evidence

Rendering a crafted tool output through `ui.RenderItem` at width 80:

```
input:  "hello\x1b[2Jworld\x1b]52;c;aGF4\x07 \r\n"
output: "⚙ bash $ ls\n  hello\x1b[2Jworld\x1b]52;c;aGF4\a \r  ...padding..."
```

Both `CSI 2J` (erase display) and `OSC 52` (clipboard write) survive to the
returned string. The same holds for `KindUser`.

`KindAssistant` is currently *incidentally* safe: glamour discards the escapes
while rendering markdown (`internal/ui/markdown.go:44`). That is a side effect
of the markdown pipeline, not a deliberate defense, and it disappears if the
assistant path ever bypasses glamour.

## Affected item kinds

- `KindTool` — `ToolBlock.Output` and `ToolBlock.Arguments`.
- `KindError` — embeds cake's stderr tail (`internal/app/update.go:466-471`).
- `KindWarning` — embeds the raw malformed-line snippet
  (`internal/app/update.go:424`).
- `KindUser` — the echoed prompt (low risk, but same path).
- `KindHook` — embeds hook stderr (`internal/app/update.go:535-538`).

## Fix Direction

`internal/ui` already depends on `github.com/charmbracelet/x/ansi`
(`internal/ui/toolblock.go:10`), so `ansi.Strip` is available with no new
dependency.

Sanitize untrusted text at a single choke point in `RenderItem`, before any
styling:

1. Strip ANSI escape sequences with `ansi.Strip`.
2. Separately drop or replace remaining C0 control bytes — `ansi.Strip` removes
   escape sequences, not bare `\r`, `\b`, or `\x00`. Keep `\n`; decide
   explicitly whether `\t` is expanded or kept.

Do not sanitize inside `internal/app`: keeping it in `ui` preserves the
side-effect-free rendering boundary and means the debug log still records the
raw bytes, which is where raw content is supposed to live.

Consider whether stripping should be unconditional or whether a future
"render tool output as-is" mode is wanted; unconditional is the safe default
and no current feature needs escapes to survive.

- User docs: README.md "Known limitations" now states that terminal control

- ADR: required and written — ADR 005, "Untrusted stream content is sanitized
  at the ui render boundary". It records the unconditional-stripping decision,
  the single-choke-point placement, tab expansion, and the loss of tool colors.

## Implementation Notes

- New `ui.Sanitize` (`internal/ui/sanitize.go`): `ansi.Strip`, then tabs to
  four spaces, drop remaining C0/C1 and DEL, keep `\n`, replace invalid UTF-8.
  Clean text returns unchanged with no allocation.
- Applied at `ui.RenderItem` (item text, and tool name/output/summary in
  `renderTool`) and at `ui.StatusLine` field values. `Status.State` is exempt:
  callers compose it from the styled spinner, not stream content.
- Tool arguments are sanitized *after* `SummarizeToolArgs`, because control
  characters arrive JSON-escaped and only become real control bytes once
  decoded.
- Sanitization works on copies; timeline items and shared `*ToolBlock`s are not
  mutated, so the per-item render cache and resize re-render are unaffected.
