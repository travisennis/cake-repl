# Add semantic UI theme roles for terminal chrome

## Summary

Improve cake-repl's visual system by expanding the current flat `ui.Theme` into semantic roles for app chrome, prompt composition, timeline metadata, status segments, and markdown integration. The current theme has basic item styles, a faint rule, and a reverse status bar, which makes future UI improvements likely to invent ad hoc lipgloss styles instead of reusing consistent tokens. This task should create the shared styling foundation for subsequent prompt, timeline, status, and markdown polish.

Written against commit `a9b0ced`.

## Evidence

- `internal/ui/theme.go:6` — `Theme` currently exposes only timeline item styles plus `Rule` and `StatusBar`; there are no semantic roles for prompt borders, labels, hints, muted metadata, status keys/values, or chrome accents.
- `internal/app/view.go:16` — the top-level view renders a simple full-width rule between timeline and input, so the only app chrome distinction is a horizontal line.
- `internal/ui/status.go:12` — `StatusLine` renders every segment with one reverse-video style and `│` separators, so status semantics are not represented in the theme.
- `internal/ui/timeline.go:57` — timeline rendering relies on per-kind glyph/color styles, which gives little shared hierarchy for labels, metadata, or separators.

## Fix Direction

Add semantic styles to `internal/ui.Theme` while preserving existing field names or updating all call sites in one scoped change. Prefer named roles such as prompt border/title/hint, focused input text or placeholder accents if usable through Bubbles styles, muted metadata, section rule, status key/value, and timeline separator/accent. Keep styles in `internal/ui` and continue to rely on lipgloss/termenv so `-no-color` remains readable with no ANSI escapes in ASCII mode. Do not change slash commands, key bindings, cake subprocess behavior, config shape, or session behavior. If the desired visual treatment requires replacing `textarea.Model` or adding a new dependency, stop and record that design decision instead of expanding scope.
