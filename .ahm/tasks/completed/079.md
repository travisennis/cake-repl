# Align AGENTS.md with the ahm v2 records-only surface

## Problem

`ahm` v2 (prerelease installed on this machine; upstream migration guide:
`docs/guides/workflow-upgrades.md` in
[travisennis/ahm](https://github.com/travisennis/ahm/blob/master/docs/guides/workflow-upgrades.md))
reduces `ahm` to a records CLI for tasks under `.ahm/tasks/` and ADRs under
`docs/adr/`. `intake`, `context`, `audit`, `onboard`, `upgrade`,
`task groom`, and `task work` are gone, and research notes and ExecPlans stop
being ahm-managed record families.

`AGENTS.md` step 1 of the operating loop still says:

```text
1. Use `ahm` intake first for tasks, ExecPlans, ADRs, or research; classify
   direct code, CLI, docs, or repository work immediately.
```

Observed failure: `ahm intake` exits with `unknown command "intake" for
"ahm"`, so the first step of the operating loop is dead on the installed
binary. The project-owned procedure documents added under `docs/workflow/`
and the relocated `docs/exec-plans/` tree have no route from `AGENTS.md`, so
no agent learns where a design plan belongs or that task/ADR practice is now
project-owned prose.

## Scope

`AGENTS.md` only:

- Replace the `ahm intake` step with decision-routed classification that
  matches the v2 surface.
- Add a route for ahm-managed records and planning that points at the task,
  ADR, and ExecPlan procedure documents, states that `ahm` manages tasks and
  ADRs only, and says where design plans live.
- Note that large or cross-cutting work requires a design plan under
  `docs/exec-plans/`.
- Have the handoff name the route taken and the documents loaded.

## Expected observable behavior

An agent reading `AGENTS.md` classifies a request against `ahm` without
invoking a removed command, and can reach the task, ADR, and ExecPlan
procedures from the routing table.

## Acceptance Criteria

- `rg -n "ahm intake" AGENTS.md` returns nothing.
- Every `docs/...` link added to `AGENTS.md` resolves on disk.
- The task, ADR, and ExecPlan procedures are reachable from `AGENTS.md`
  routes.

## Verification

- `rg` for stale v1 command names in `AGENTS.md`.
- Link check of every path added.
- Behavior probe deferred: the probe that would establish effect is a fresh
  session given a task-backed request, checking that the agent loads
  `docs/workflow/tasks.md` and does not invoke `ahm intake`.

## Acceptance Notes

- Operating-loop step 1 now routes on the decision ("If it names a task or an
  ADR, inspect it through `ahm` before choosing implementation work") and no
  longer names a removed command. `rg -n "ahm
  (intake|context|audit|onboard|upgrade)|ahm task (groom|work)" AGENTS.md`
  returns nothing.
- All 17 relative links in `AGENTS.md` resolve on disk (checked against the
  filesystem; one external URL skipped).
- Added the "Tasks, ADRs, And Design Plans" route, so the project-owned
  procedure prose added for the v2 release is reachable: each of
  `docs/workflow/tasks.md`, `docs/workflow/adrs.md`, and
  `docs/workflow/exec-plans.md` carries a retrieval reason, the trigger nouns
  are task/ADR/decision/design plan rather than paths, and the procedure stays
  in the linked documents.
- The operating loop states that large or cross-cutting work requires a design
  plan under `docs/exec-plans/`, and the handoff now asks for the route taken
  and the documents loaded.
- **Preflight** (subagent, one combined pass at XS scale): no required edits.
  Its single finding was that a "never hand-edit a generated index" clause
  added in the first draft restated rules owned by `docs/workflow/tasks.md`

  `docs/exec-plans/*` were ahm-generated. The clause was removed and replaced
  by the scope fact that `ahm` manages only task and ADR records.
- Docs-only change to one file: `just ci` skipped, because every `ci` target is
  Go-side, matching the docs guidance in `CONTRIBUTING.md`.
- Deferred probe unchanged: effect is unverified until a fresh session given a
  task-backed request is observed loading `docs/workflow/tasks.md`.
