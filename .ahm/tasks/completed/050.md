# Fix multi-line prompt corruption in the persisted history round-trip

**Code-review finding (2026-07-19), high confidence.** Enter inserts a newline
(Ctrl+S submits), so multi-line prompts are the normal case — and they corrupt
the `-history-file` round-trip.

## Problem

`persistHistory` appends the raw prompt text plus `"\n"`
(`internal/app/update.go:288-300`), embedding real newlines in the file.
`loadHistory` reads the file line-by-line with `bufio.Scanner` and treats each
line as one entry (`internal/app/model.go:126-155`).

Consequences:

- A 5-line prompt becomes 5 unrelated history entries on the next start.
- The `maxHistoryEntries` cap and the rewrite-on-load trim count *lines*, not
  prompts.
- Up-arrow recall after restart returns fragments of prompts.

In-memory history within one session is unaffected; only persistence is broken.

## Relevant Files

### To modify
- `internal/app/update.go` — `persistHistory`: encode entries so one entry is
  one record.
- `internal/app/model.go` — `loadHistory`: decode the same encoding.

### Tests
- `internal/app/history_io_test.go` — round-trip a multi-line prompt through
  persist + load; assert one entry comes back byte-identical.

## Fix Direction

Use JSON Lines for newly written entries: marshal each prompt as one JSON
string followed by a newline. On load, decode JSON-string records and fall
back to treating non-JSON lines as legacy plain single-line entries. When the
load-time cap rewrites the file, write every retained entry in the new JSONL
form. This keeps record boundaries unambiguous for newlines and backslashes
without corrupting existing plain history files.

## Documentation / ADR Notes

- User docs: no change required; this restores multi-line prompts as single
  history entries without changing the documented flag or path.
- Guardrails: no change required; file permissions and best-effort I/O remain
  unchanged.
- ADR: not required because this is a backward-compatible correction to a
  private persistence encoding, not a new persisted-state contract.

## Acceptance criteria

- [x] A multi-line prompt persisted to the history file loads back as a single

- [x] Existing single-line history files still load unchanged.
- [x] `maxHistoryEntries` trimming counts entries, not physical lines.

## Acceptance Notes

- **Design**: Each entry is stored as `\x02` + JSON-encoded string + newline,
  appended atomically via `O_APPEND`. The `\x02` prefix unambiguously marks
  JSONL records; lines without it are treated as plain text (legacy fallback).
  No file header, no migration lock, no temp-file rename.
- `TestLoadHistoryMultilineRoundTrip` verifies the full round-trip through
  `persistHistory` → file → `loadHistory`, including newlines and special
  characters.
- `TestLoadHistoryMixedFormat` verifies that `\x02`-prefixed and plain-text
  lines coexist correctly in the same file.
- `TestLoadHistoryLegacyQuotedString` verifies that JSON-looking plain text
  (e.g., `"hello"`) is preserved verbatim when it lacks the `\x02` marker.
- `TestLoadHistoryOverCap` validates the cap-triggered rewrite converts all
  entries to `\x02`-prefixed JSONL.
- **Preflight**: retained the existing bounded streaming scanner instead of
  adding a whole-file read and unrelated size cutoff, and shared one record
  encoder between append and cap-rewrite paths.
- Verified with `go test -race -count=1 ./...` — all packages pass.
- Windows: `GOOS=windows go build ./...` succeeds.
- Post-preflight `just ci` passed format, tidy, vet, race/coverage tests, and
  lint, then stopped at `govulncheck` on GO-2026-5970 in the existing
  `golang.org/x/text@v0.30.0`; `just build` and `just release-check` passed
