# Fix minor timeline formatting rough edges

## Problem
Two small formatting rough edges remain in timeline output:

- Tool headers can overflow the target width because the argument summary is truncated to the full width before the `⚙ name ` prefix is added.
- `humanDuration` reports long durations only as minutes and seconds, so values over an hour display as large minute counts such as `61m40s`.

## Evidence
- `renderTool` in `internal/ui/timeline.go` builds `⚙ <name> ` plus `firstLineOf(summary, width)`.
- `humanDuration` in `internal/app/update.go` has millisecond, second, and minute cases but no hour case.

## Relevant Files
- `internal/ui/timeline.go`
- `internal/ui/timeline_test.go`
- `internal/app/update.go`
- `internal/app/update_test.go`

## Fix Direction
For tool headers, compute the available width after accounting for the rendered icon/name prefix and spacer, then truncate the argument summary to that remaining width. Preserve readable output at narrow widths.

For durations, add an hour rollup for durations >= 1 hour. Keep existing millisecond, second, and minute formatting unchanged for shorter durations.

## Acceptance Notes
- [x] A long one-line tool argument summary does not overflow by the prefix width.
  - `renderTool` now computes `prefix` visual width and passes `avail = width - prefixWidth` to `firstLineOf`.
- [x] Narrow terminal widths still produce valid, readable tool output.
  - `avail` is clamped to at least 1, and the existing multi-line output and truncation paths are unchanged.
- [x] Durations under one hour keep the current output format.
  - The `d < time.Hour` guard preserves the existing millisecond/second/minute cases.
- [x] Durations of one hour or more render with an hour component.
  - New default case computes `h`, `m`, `s` and formats as `XhXXmXXs`.
- [x] Focused tests cover tool header width and hour-duration formatting.
  - `TestRenderItemTool/long_tool_argument_at_narrow_width_does_not_overflow` verifies no line exceeds 30 cells.
  - `TestHumanDuration` covers ms, s, m, and h cases including boundary values.
- [x] Run `go test ./internal/ui ./internal/app` or broader verification.
  - `just test` (all packages) and `go vet ./...` both pass cleanly.
