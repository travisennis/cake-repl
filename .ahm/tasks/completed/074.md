# Show (thinking) timeline marker for reasoning, coalesced per burst

## Context

Not all providers populate the `summary` field on cake's `reasoning` stream-json
events, so today an empty summary silently disappears: `internal/app/update.go`
drops the event entirely (`if text != ""`). The REPL gives no indication that
thinking/reasoning occurred.

Decided (with Trav, 2026-08-01):

1. Show a `(thinking)` timeline marker whenever reasoning occurs — the user does
   not need the thinking content itself, just an indication it is happening/has
   happened.
2. Dedup/coalesce: one marker per reasoning burst. A burst is consecutive
   `reasoning` events; any other event (assistant message, function_call,
   function_call_output, hook_event, task_complete) ends the burst.
3. Marker-only: stop rendering `Reasoning.Summary` entirely. This is a small
   regression of the documented "reasoning summaries" surface (README line,
   cli-and-user-output guardrail note); update those docs to match.

## Scope

- `internal/app/update.go`: on `cake.Reasoning`, append a `(thinking)` item only
  when the last timeline item is not already a reasoning marker; otherwise no-op.
- `internal/cake/events.go`: untouched — `Reasoning` decode stays as-is
  (forward-compat, unknown fields ignored). No parser change.
- Tests: `update_test.go` reasoning cases keep passing (they assert trim /
  pendingCalls behavior, not text); add a coalescing test (two consecutive
  reasoning events → one marker; reasoning after a tool event → new marker).
- Docs: update README "reasoning summaries" wording and
  `docs/guardrails/cli-and-user-output.md` rendering note.
