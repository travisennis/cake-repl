# Avoid double JSON unmarshal in stream parser

## Problem
`parser.ParseLine` unmarshals each nonblank stream-json line twice: once into `StreamEnvelope` to identify the event type, then again into the concrete typed event. This is currently negligible, but it is avoidable parser work if timeline/session performance becomes important for large streams.

## Evidence
- `internal/cake/parser.go` unmarshals into `StreamEnvelope` at the top of `ParseLine`.
- The local `decode` helper unmarshals the same line again for every known event type.
- Parser tests already cover known event types, unknown event forward compatibility, malformed lines, unknown fields, and blank lines.

## Relevant Files
- `internal/cake/parser.go`
- `internal/cake/events.go`
- `internal/cake/parser_test.go`

## Fix Direction
Use a lightweight envelope containing `type` and a `json.RawMessage` representation, or an equivalent approach that avoids unnecessary string/byte conversions and repeated full unmarshal work while preserving behavior.

Unknown event types must still return `Unknown` with the raw trimmed line, unknown fields on known types must remain ignored, malformed JSON must still surface as an error, and blank lines must still return nil event/nil error.

## Acceptance Notes
- [x] `ParseLine` avoids re-unmarshalling the full line just to decode known event payloads where practical.
  - `StreamEnvelope` now implements `UnmarshalJSON` to capture both `Type` and the raw bytes (`json.RawMessage`) in one pass.
  - The concrete event decode reuses `env.Raw` instead of re-converting `string`→`[]byte`.
  - `bytes.TrimSpace` keeps the trimmed data as `[]byte`, eliminating the `[]byte`↔`string` conversions.
  - The `decode` closure is removed, along with its allocation.
- [x] Existing parser behavior for known, unknown, malformed, unknown-field, and blank lines is unchanged.
- [x] Parser tests remain focused and hermetic.
- [x] Run `go test ./internal/cake` — all 24 tests pass.
