# Avoid full timeline rebuild on every event

## Problem
Timeline item rendering is cached, but every new event still calls `syncViewport`, which joins all rendered items and calls `viewport.SetContent` with the full timeline. Over a long session this makes append/update behavior roughly O(n^2) in the number of rendered timeline items.

## Evidence
- `appendItem` and `rerenderItem` call `syncViewport` in `internal/app/model.go`.
- `syncViewport` performs `strings.Join(m.rendered, "\n\n")` and `m.timeline.SetContent(...)` for every append or item rerender.
- Cake emits whole messages rather than token deltas, so this is not urgent for typical sessions but is the likely next bottleneck for very long sessions.

## Relevant Files
- `internal/app/model.go`
- `internal/app/model_test.go`
- `internal/ui/timeline.go`

## Fix Direction
Keep the existing per-item render cache, but avoid reconstructing the full viewport content on every append where possible. A reasonable implementation can maintain a cached full timeline string/builder alongside `rendered`, invalidate it on width changes and `/clear`, and update it incrementally for append-heavy paths.

For in-place rerenders, preserve correctness first. It is acceptable for rerendering a prior tool block to rebuild the full content if appends become cheap and tests prove the cache remains consistent.

## Acceptance Notes
- [x] Appending a timeline item does not join all rendered items on the hot path; it renders the new item and extends cached timeline content.
- [x] Width changes still fully rerender all items at the new width and rebuild cached timeline content.
- [x] `/clear` resets items, rendered entries, pending tool indices, and cached timeline content.
- [x] In-place tool output updates still rerender the changed item, rebuild cached timeline content, and preserve bottom-pinning behavior.
- [x] Existing timeline cache tests were updated to cover cached timeline content, plus a regression test proves append does not rebuild from existing rendered entries.
- [x] Ran `go test ./internal/app ./internal/ui` and `just ci`.

## Preflight Notes
- App-side append no longer joins all rendered items, which satisfies this task's scoped hot-path target.
- Bubble viewport `SetContent(string)` still re-splits the full content internally on each viewport update; removing that would require a larger viewport/content-model change and is intentionally left out of this task.
