# Expand tabs to real tab stops in ui.Sanitize

Follow-up to task 061 and
[ADR 005](../../../docs/adr/005-untrusted-stream-content-is-sanitized-at-the-ui-render-boundary.md).

## Problem

`ui.Sanitize` (`internal/ui/sanitize.go`) replaces every tab with a fixed
four-space run. That was chosen for simplicity while closing the terminal
injection hole; it is not the best available behavior, and it trades one
defect for another.

Before task 061, raw tabs reached the terminal, which advanced the cursor to
the next 8-column tab stop, while `lipgloss.Width("\t")` measured them as 0
(verified). Alignment looked right; the wrapping and padding math was wrong.

After task 061, the width math is honest but column alignment is wrong:
tab-separated output (`go test` output, `column -t`, `df`, `docker ps`,
hand-made ASCII tables in tool output) no longer lines up, because a fixed
four-space run is not a tab stop.

Both defects are avoidable. Expanding to real tab stops gets honest width
*and* correct alignment.

## Relevant Files

### To modify
- `internal/ui/sanitize.go` — `Sanitize` and the `sanitizeTab` constant.

### Tests
- `internal/ui/sanitize_test.go` — direct unit cases.

## Fix Direction

Expand tabs to eight-column stops, matching the conventional terminal default. Tab stops are relative to column zero of each sanitized string, and the column resets after every newline. Strip ANSI sequences first; while scrubbing, measure contiguous printable runs with `ansi.StringWidth` so CJK, emoji, combining sequences, and other grapheme-width cases advance by rendered cells rather than rune count. Dropped control characters do not advance the column. For a tab, emit `8 - (column % 8)` spaces. Remove the fixed `sanitizeTab` replacement and do not thread a terminal-screen origin through `RenderItem`. Update the README known limitation and CLI/output guardrail. Update ADR 005's obsolete consequence as a clarification of the existing sanitize-and-expand decision; no new ADR is required.

## Acceptance criteria

- [x] Tabs expand to the next eight-column stop rather than a fixed-width run.
- [x] Column tracking resets after each newline.
- [x] Unit tests cover tabs at column zero, exactly on a stop, between stops, and on multiple lines.
- [x] Tests cover CJK, emoji, and combining-character text before a tab and assert rendered cell alignment.
- [x] Existing terminal-injection, no-color, wrapping, and maximum-line-width tests continue to pass.
- [x] A manual no-color render confirms tab-separated tool output aligns without emitting tab bytes (verified via the automated ASCII-profile render test `TestRenderItem_TabSeparatedTableAligns`; an interactive TUI run was not possible in this environment).
- [x] README, the CLI/output guardrail, and ADR 005 no longer describe fixed four-space expansion.
- [x] `just ci` passes.
